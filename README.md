# SVG3D：三维空间描述语言（原型 v0.1）

AI 重建三维场景时，常见做法是体素或点云，即逐格判断“这里有没有东西、是什么颜色”。人描述空间的方式不一样：先说“它在谁上面、贴着谁、从哪里连到哪里”，至于每个东西的具体形状，有很多种变体都可以。

SVG3D 想做的是 3D 版的 SVG：一种文本化、声明式的空间描述语言。它和 X3D 或 glTF 的区别在于：

| | 体素 / 网格 | X3D / USD | **SVG3D** |
|---|---|---|---|
| 描述单位 | 格子、三角面 | 基本体 + 绝对坐标 | 基本体 + **空间关系** |
| 位置从哪来 | 逐点给出 | 逐个给出坐标 | **从关系求解**（on / against / inside / span …） |
| 改一处 | 局部重画 | 手动挪所有相关物体 | 依赖它的物体跟着动 |
| 对 AI 友好 | 只能拟合像素 | 需要精确数值推理 | 写的是关系，坐标交给求解器 |

语言本身**只有客观几何**，没有“墙、门、桥”这类功能词。门洞就是 `subtract` 挖掉的一块，楼梯就是带 `steps` 的 `span`。功能语义可以用 `#标签` 附加上去，但不影响几何。

## 一个例子

```
box pad size=26,2,26 on=ground[0.25,1,0]

group rocket on=pad {
  cyl stage1 r=2.4 h=28
  cyl stage2 r=2 h=14 on=stage1
  cone nose  r=2 h=7 on=stage2
  repeat fins n=4 turn=90 {
    wedge fin size=3.5,6,0.4 turn=180 at=stage1.w/2,0,0 pin=bottom-right
  }
}

span arm from=tower.decks.5.deck.top-right-front to=rocket.stage2[-0.6,0.14,-0.6] section=1.6,0.3
box annex size=12,8,14 against=hangar.body.right align=back,bottom
```

把 `stage1` 改高，`stage2`、`nose` 和摆臂的终点都会跟着移动。

## 语言

### 坐标约定
单位是米，Y 轴朝上，`+x = right/east`，`+z = front/south`。每个物体有自己的局部坐标系，可以任意三维旋转；镜像副本的坐标系是反射的。**基本体的原点在底面中心**，所以不写任何关系的物体默认立在父坐标系的原点上。

### 实体

| 写法 | 说明 |
|---|---|
| `box size=w,h,d` | 长方体 |
| `cyl r= h= axis=y` | 圆柱，`axis` 可取 x / y / z |
| `cone r= r2= h= axis=y` | 圆台（`r2=0` 时为圆锥） |
| `sphere r=` | 球 |
| `wedge size=w,h,d` | 楔形，+x 一侧高 |
| `revolve profile=[(r,y); …] smooth=true angle=360` | 一条轮廓线绕竖直轴旋转（罐体、整流罩、喷泉），自动在轴上封口 |
| `span from=A to=B section=w,t` | 连接空间中两点的实体；`r=` 表示圆杆，`steps=n` 表示台阶；`pin=bottom` 让底面贴着连线。梁的局部框架沿 A→B，所以 `on=span` 能放在斜梁真正的顶面上 |
| `span from=A drop=B dir=down` | 从 A 沿某个方向（默认竖直向下）一直延伸，直到碰到 B 的面（立柱、桩、落地的梯子） |
| `sweep path=C profile=rect section=w,t` | 截面沿曲线扫掠（弯道、拱、扶手）；`profile=circle r=` 为圆管；`profile=[(u,v); …]` 为任意多边形截面（工字钢、钢轨）；`path` 也可以是点列表 |
| `pipe path=[A; B; C] r=` | 圆管的简写，折线拐角自动倒圆；`smooth=true` 变成平滑曲线 |

### 曲线

曲线是一等公民，但**不是实体**：它可以被引用、在上面取点，也可以让实体沿着它生成。

| 写法 | 说明 |
|---|---|
| `arc r= angle=a0,a1 rise= plane=xz` | 圆弧。角度 0 指向 +x，俯视逆时针；`rise` 让它边转边升；`plane=xy/zy` 为竖直平面里的弧（拱） |
| `helix r= pitch= turns=` | 螺旋线 |
| `bezier path=[P0; P1; …]` | 贝塞尔曲线，任意阶，只经过首尾点 |
| `spline path=[…] closed=true` | 经过每个点的样条 |
| `line path=[…]` | 折线 |
| `C.start` `C.mid` `C.end` `C[0.3]` | 曲线上按弧长取点，可以用在任何需要点或锚点的地方 |
| `repeat n= along=C orient=yaw { … }` | 沿曲线等距分布，实例的局部 x 跟随切线、z 朝曲线外侧。`orient=yaw` 只转向、保持竖直（路灯）；`full` 连坡度一起跟随（枕木）；`none` 不转 |

### 镜像与旋转（复制关系）

镜像和旋转是**关系**，不是一次性复制：副本始终是原物体的镜像或旋转像，原物体变了，副本跟着变。副本里的名字照样可以引用，例如 `tower2.decks.5.deck`。

| 写法 | 说明 |
|---|---|
| `mirror R of=A across=B axis=x` | R 是 A 关于“过 B 中心、法线为 B 的 x 轴”的平面的镜像 |
| `mirror R of=A across=B.right` / `across=ground.top` | 镜像面就是 B 的某个面，可以是水平面（倒影） |
| `mirror across=x { … }` | 对称组：子物体加上它们的镜像（生成在 `.mirrored` 下） |
| `rotate R of=A about=B axis=z angle=90` | R 是 A 绕“过 B、方向为 axis”的轴转 90° 的像。`axis` 可以是 x/y/z、向量，或锚点（如 `hub.front`），默认竖直 |
| `rotate n=5 about=B axis=… { … }` | 旋转对称：原物体加 5 个副本（生成在 `.r1` … `.r5` 下），`angle` 默认 360/(n+1)。风车叶片就是 `axis=z` |

镜像是真正的反射，左右手性会翻转：楔形的坡向、楼梯的走向都会跟着反过来。而副本内部的关系在它自己的坐标系里保持不变，空间事实会写成 `mirrored.ramp against mirrored.house.right`。

### 关系（决定位置）

| 写法 | 含义 |
|---|---|
| `on=B` | 自己的底面中心放到 B 的顶面中心（`on=B[u,1,w]` 可以放在顶面上的任意位置） |
| `under=B` | 自己的顶面贴住 B 的底面 |
| `against=B.left` | 贴住 B 的左面，自动选用自己朝向它的那个面 |
| `inside=B` | 中心对中心放进 B |
| `at=x,y,z` / `at=B.top` | 把自己的 `pin` 点（默认底面中心）放到某一点 |
| `align=left,back` | 定位后再与参照物的这些面对齐；`x`/`y`/`z` 表示中心对齐；`alignto=C` 可以换一个参照物 |
| `gap=d` | 沿关系的法线方向留空，负值表示嵌入 |
| `offset=x,y,z` | 最后再整体平移 |
| `pin=bottom-left` / `pin=u,v,w` / `pin=origin` | 自己身上哪个点作为定位点，也是旋转的支点 |

### 朝向

| 写法 | 含义 |
|---|---|
| `turn=deg` | 绕自己的竖直轴转（俯视逆时针） |
| `tilt=deg` | 顶部倒向 front（+z） |
| `roll=deg` | 顶部倒向 right（+x） |
| `rot=(x,y,z,deg)` | 绕任意轴（局部坐标）转 |
| `aim=B` / `aim=(x,y,z)` | 让自己的 front 指向目标，并尽量保持直立；`aimwith=top` 换成别的面（如炮管、天线） |

组合顺序是：基准朝向 → `turn` → `tilt` → `roll` → `rot`，都绕 `pin` 点转。

**朝向继承**：使用 `on/under/against/inside` 时，物体默认继承参照物的三维朝向，这时上面这些角度都是相对参照物的。所以贴在转了 30° 的掩体上的楔形会自动与它的面平行，放在斜梁上的箱子会自动平贴在斜面上。`at` 是纯粹的点定位，不继承朝向。

### 锚点与度量
- `B.top`、`B.top-left`、`B.top-left-front`：面、棱、角，也可以用 `east/west/north/south/up/down`
- `B.origin`：B 的局部原点
- `B[u,v,w]`：包围盒内的归一化坐标，每个分量取 -1..1
- `B.top+(0,2,0)`：锚点加偏移
- `B.w`、`B.h`、`B.d`：B 的尺寸，可以写进表达式（如 `at=stage1.w/2,0,0`）
- `B.top.y`、`B.x`：锚点在当前物体父坐标系里的坐标分量（如 `h=deck.bottom.y`，让柱子刚好顶到平台底）
- 路径：`hangar.body.right`、`tanks.0.tank`（阵列实例按序号命名）。名字从当前层逐层向外查找，最后按全局唯一名查找

### 变量、集合与语义

语言本身只有客观几何；**语义由使用者用集合定义**。`group` 和集合是两回事：group 是空间上的，带坐标系，会改变位置；集合是逻辑上的归类，一个对象可以同时属于很多集合，不会因此移动。

```
let bridge_len = 36                       // 变量：数、向量、对象、集合都可以
let solids = kind(box, cyl, wedge)

concept pier  = kind(cyl) & on(river) & supports(kind(box))   // 立在水里、托着东西的柱子
concept deck  = kind(box) & on(pier, 2)                        // 架在至少两根桥墩上的板
concept roof  = kind(wedge) & on(kind(box))
concept tall_building = kind(house) where h > 6                // 模板名就是使用者定义的类型

style pier mat=stone                      // 按语义上色：同一份布局，换一套 style 就换风格
check "没有悬空的实体" solids - on(all()) - ground
repeat lamps over=#pillar { cyl pole on=it }   // 对每个成员各做一次
box roof on=#wall                         // 集合也能当参照物（用它们的总包围盒）
```

| 写法 | 说明 |
|---|---|
| `let 名字 = 表达式` | 变量。在所在块内整体可见，惰性求值，与书写顺序无关；最外层的 let 在模板里也可见 |
| `#tag` · `kind(box, house)` · `a.*.b` · `all()` · `[a; b; c]` | 构造集合：按标签、按类型（包括模板名）、路径通配、全部对象、列表 |
| `children(S)` · `descendants(S)` | 下级 |
| `A \| B` · `A & B` · `A - B` | 并、交、差（`-` 比 `&`、`\|` 结合得紧） |
| `S where 条件` | 逐个成员筛选；条件里可以用 `w h d`（自身尺寸）、`x y z`（世界中心）、`kind`、`name`、`it`（成员本身），以及 `> < >= <= == !=`、`and or not` |
| `on(S, k)` · `supports(S, k)` · `against(S)` · `inside(S)` · `contains(S)` · `touching(S)` | 按空间关系筛选：立在 S 上的、承托着 S 的、与 S 贴面的……`k` 表示至少与 S 中几个成员有这种关系。组里任何一个物体满足，组就满足 |
| `concept 名字 = 集合` | 定义一个语义词。求解后，编译器按定义在场景里识别成员，结果显示在预览器的「语义」标签里 |
| `style 集合 mat=… color=…` | 按集合改外观，作用于成员和它们的所有下级，后写的覆盖先写的 |
| `check "说明" 表达式` | 规则检查：结果是集合时，空集为通过，否则列出违反的对象；结果是真假值时，为真即通过 |
| `repeat over=集合 { … }` | 对每个成员各做一次，`it` 指向当前成员 |
| `sin cos tan sqrt abs min max floor ceil round pow count` | 函数，角度用度 |

两条规则：
- **关系谓词只能用在语义层。** `on()`、`supports()` 等依赖求解后才有的空间事实，所以只能用在 concept、style、check 里，不能用来决定位置（否则就是循环）。`#tag`、`kind()`、路径通配不依赖事实，在哪里都能用。
- **概念有自己的命名空间。** 概念只在 concept、style、check 里可见，不会和几何里的同名对象冲突。`let` 和模板参数则会遮蔽同名对象。

### 多对象模式

`concept` 回答“哪些对象是 X”。`pattern` 回答“哪几个对象一起构成 X”：给每个角色起名字，写出它们之间的关系，编译器在场景里搜索所有满足约束的组合。

```
pattern home(body, roof*, door) {          // 名字带 * 的是集合角色
  body in kind(box) where h > 2            // 角色 in 集合：候选范围
  roof in kind(wedge)
  door in kind(box) where h < 2.5 and d < 0.5
  roof on body                             // 甲 关系 乙：on / supports / against / inside / contains / touching
  door against body
  count(roof) >= 1                         // 其余的行是布尔表达式，角色名可以直接用（如 body.w > 4、a != b）
}
style home.roof mat=tile                   // 名字.角色 取出该角色的全部绑定；count(home) 是匹配次数
```

- 单个角色逐个枚举；集合角色绑定为“满足全部约束的所有成员”，例如一个房间的全部墙
- 一个对象不会同时扮演两个角色；同一组对象换个顺序算同一个匹配
- 一条关系约束里最多一个集合角色，且它要单独站在关系的一边

### 按语义替换变体

```
def planks(w=1, h=1, d=1) { … }            // 模板声明了 w h d，就会收到外包络的尺寸
variant deck use=planks                    // deck 可以是任何集合，包括依赖空间事实的概念
```

这是“语义决定外包络，变体只负责填满它”：
- 被替换的对象仍然参与求解，它的外包络、锚点和与其他物体的关系都不变，只是不再渲染；变体挂在它下面，名字是 `原对象.skin`
- 因为可以按概念（依赖空间事实）选择，有 variant 时会**编译两遍**：第一遍求解并识别语义，第二遍换上变体
- 变体只是外观，对语义层不可见：集合、概念、模式、检查和空间事实都按原来的外包络算
- 模板自己写了材质的部分保留自己的材质，其余的继承原对象的材质或样式

### 编译期的随机与条件

它们**不是运行时的东西**。场景是静态的：同样的源码永远编译出同样的场景，就像模板引擎生成页面。

| 写法 | 说明 |
|---|---|
| `let seed = 7` | 全局种子，换一个数就换一种结果 |
| `rand(键…)` · `uniform(最小, 最大, 键…)` · `choose(甲, 乙, …)` | 确定性随机：`hash(种子, 调用位置, 键)`。调用位置 = 所在对象的路径 + 属性名 + 该表达式里第几个随机调用，所以阵列的每个实例、同一行的两个调用都互不相同 |
| `if 条件 { … } else if 条件 { … } else { … }` | 展开时选择要生成哪些语句。条件必须在展开时就能确定：参数、let、阵列下标、随机数 |
| `if(条件, 甲, 乙)` · `a % b` | 表达式里的选择、取余 |

### 构造

| 写法 | 说明 |
|---|---|
| `group { … }` | 分组，组有自己的坐标系，包围盒是子物体的并集 |
| `union` / `subtract` / `intersect { … }` | 布尔运算；`subtract` 表示第一个子物体减去其余的 |
| `repeat n=4 step=x,y,z turn=deg center=true { … }` | 阵列。`n=(2,1,3)` 为三维网格；同时设 `step` 和 `turn` 会得到螺旋；子语句里可以用 `i j k idx` |
| `def name(p=默认值, …) { … }` | 参数化模板，用 `name id p=值 on=…` 实例化。默认值如果是向量要加括号：`size=(4,3,2)`。模板声明的参数优先于同名的定位关键字（模板可以有自己的 `gap`、`turn`） |
| `material name color= metal= rough= opacity=` | 材质，用 `mat=name` 引用，子物体会继承 |
| `#tag` | 任意标签 |

表达式支持 `+ - * /`、括号、向量 `(x,y,z)`，以及引用模板参数和阵列下标。

## 求解是怎么做的

1. **解析**：把源码解析成语句树
2. **展开**：模板实例化，阵列复制成实例（`tanks.0`、`tanks.1`……）
3. **求解**：每个物体的局部变换都由它的关系惰性计算得出，依赖关系自动排序。计算锚点时，会把参照物的点从参照物的坐标系，经过最近公共祖先，换算到自己的父坐标系
4. **后置物体**：如果组里的某个子物体引用了组外的对象，它的位置就依赖组的位置，而组的位置又依赖组的尺寸。求解器会自动识别这种情况，把这个子物体标为“后置”，它不参与组的尺寸计算，从而打破循环。真正的循环依赖会报错，并给出行号
5. **输出**：几何条目（叶子实体和布尔树）交给渲染器；编译器同时**反向推导空间事实**

### 反向：空间事实
求解完成后，编译器会检查所有物体之间的关系，并用同一套词汇写出来：

```
rocket.nose on rocket.stage2
annex against hangar.body.right
berm against bunker.left        ← 在掩体自身坐标系里判断，旋转后仍然成立
spare inside hangar.body
```

这是“模型 → 语言”这个方向的雏形。重建地图时，可以先从源模型中分割出部件、拟合成基本体，再用这一步得到关系，最后生成可编辑的 SVG3D。

## 表达能力评估

为了检验这门语言，我用它写了几个刻意有难度的场景（`examples/` 下的四个示例），记录下“写不出来”或“要绕路”的地方。写过程中发现、已经补上的有：

| 缺口 | 补法 |
|---|---|
| 风车叶片要绕水平轴转 | 任意轴三维旋转：`tilt/roll/rot`、`rotate axis=` |
| 天线要对准卫星 | `aim=`（关系式朝向，而不是写角度） |
| 箱子放在斜坡上要平贴 | `on` 继承参照物的三维朝向；斜梁有真正的顶面 |
| 倒影、上下对称 | 镜像面可以是任意平面 |
| 过山车立柱要“落到地面” | `span drop=`：沿方向延伸到碰到某个面 |
| 柱高要“刚好顶到平台” | 表达式里可以取锚点坐标 `B.bottom.y` |
| 工字钢、钢轨这类截面 | `sweep profile=[(u,v); …]` 任意多边形截面 |

### 仍然缺少的（按对“重建游戏地图”的重要性排序）

**一、重建地图时会直接卡住的**
1. **引用原始网格**：雕像、车辆、复杂道具很难拆成基本体。需要 `mesh src="原模型.glb#节点"` 作为叶子节点，这样它照样能参与 on / against / mirror 这些关系。没有它，重建只能“全部用基本体近似”
2. **地形**：真实地图有坡、丘、壕沟。需要高度场或控制点地形，并且让 `on=terrain` 在任意位置贴合地表，而不是只贴合包围盒顶面
3. **面上的坐标系**：外立面上的门窗阵列、屋顶上的设备，需要“在 B 的前面上按 (u,v) 排布”，比如 `repeat on=B.front grid=…`。现在只能用包围盒锚点加偏移去凑
4. **曲面上的锚点**：圆柱侧面 θ 角处、球面经纬度。现在锚点都基于包围盒，罐体侧面的接管口只能估算
5. **不规则轮廓的实体**：L 形、多边形的建筑平面，坡屋顶（人字、四坡）。现在要靠多个 box 拼，或者用竖直 sweep 绕路

**二、关系与约束层面**
6. **多重约束**：一个物体同时满足多个关系，例如“在 A 和 B 之间、离 C 至少 2 米、不与任何东西重叠”。现在每个物体只有一个主关系，后面的关系会覆盖前面的
7. **由关系决定尺寸**：任意实体“拉伸到”某处，比如墙从柱 A 延伸到柱 B。现在只有 `span` 能这样做，box 要靠坐标表达式去算
8. **区间分布**：“在 A、B 之间均匀放 5 个”（`repeat from=A to=B`）、“在区域里按种子随机散布”（树木、杂物）
9. **单个物体沿曲线的朝向**：只放一个物体也要跟随切线（比如车站站台），现在只能写 `repeat n=1 along=`；扫掠也还不能沿路径扭转或倾侧（过山车的弯道倾角）

**三、语言机制**
10. **变体只能填满外包络**：`variant` 不改变外包络，这保证了关系不变，但也意味着“换成一种更高的墙”这类改变尺寸的替换做不到
11. **随机散布没有避让**：随机放置的物体会互相重叠，还没有“彼此至少隔开 d”的泊松盘采样或不重叠约束
12. **模式的表达力**：不支持否定（“没有门的房间”只能写成 check），也不能对两个集合角色之间加约束
13. **模块化**：大地图需要拆成多个文件，用 `import` 组合

**四、反向（模型 → 语言）**
14. 空间事实只有 on / against / inside（朝向不对齐时只有近似的 touching）。重建还需要识别**对称**（→ mirror）、**重复**（→ repeat / rotate）、**共线与等距**，以及把散乱的点**拟合成曲线**。语言已经能表达这些，但还没有提取它们的工具

**五、可以等一等的**
15. 倒角与圆角、壳体厚度、放样（loft）、自由曲面
16. 贴图与 UV、贴花
17. 玩法层的客观事实：可行走面、连通图（哪些平台通过楼梯相连）、视线与掩体。它们都能从几何推导出来，对三角洲这类 FPS 地图很有价值

### 建议的优先级
先做 **1（引用原始网格）+ 3（面坐标系）+ 14（对称与重复识别）**。这三项合起来就够做“源模型 → SVG3D”的第一版：识别不了的部件直接引用原网格，能识别的部件变成基本体和关系，再把对称和重复压缩成 mirror 和 repeat。其次是 2（地形）和 6（多重约束）。

## 下一步方向
1. **逆向管线**：源模型 → 部件分割（按材质、命名、连通性、平面拟合）→ 基本体拟合 → 关系、对称、重复的提取 → SVG3D 源码
2. **约束求解**：允许一个物体同时有多个关系，用数值求解器处理冲突
3. **拓扑与可达性**：从 span/steps 推导哪些平面互相连通
4. **导出到引擎**：Blender、Roblox、Unity，保留层级与标签
