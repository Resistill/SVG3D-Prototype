# SVG3D 演进计划

> 定位：增强三维空间的语义描述，帮助 AI **理解场景**、从源模型**重建场景**；重建之后还要能**编辑**和**风格化**。
>
> 本计划由 Fable 模型基于代码现状起草，主会话审阅并核实了其中关于代码的判断（见末尾「审阅意见」）。

## 0. 现状里的关键问题

1. **空间事实有缺陷，而且噪声大。** 朝向不对齐的一对物体，会同时输出 `on` 和近似的 `touching`（例如 `bunker on ground` 与 `ground touching bunker`）。原因是近似 touching 用的是世界包围盒（`deriveFacts`）。实测 spaceport 的 158 条事实里有 101 条是近似 touching，rotation 的 969 条里有 708 条。逆向管线以事实为地基，这必须先修。
2. **事实推导是 O(n²)**：rotation（615 个节点）编译要 556 ms，万级物体需要空间索引。
3. **每个节点的所有属性共用一个作用域**（`Solver.eval`），这会妨碍“覆盖继承来的部件的某个属性”：覆盖来的表达式需要有自己的作用域。
4. **匿名节点按序号命名**（`kind#idx`），编辑之后路径会漂移。逆向输出必须给所有节点命名。
5. **`repeat` 不继承参照物的朝向**（`orientation` 对 repeat 直接返回单位矩阵），所以“在转过角度的建筑外立面上排窗”在顶层做不到。另外，`against=B[u,v,1]` 其实已经是“面上的 (u,v) 坐标”。
6. 预览器导出的 GLB 里，mesh 的名字就是对象路径，所以第一轮闭环测试天然是“带名字”的简单难度，评测需要分难度等级。

## 1. 原则

1. **描述而非生成**：源码说明“场景是什么”。需要执行一个过程才能得到结果的构造（随机、分支、循环体内的计算）不进核心。
2. **可逆性的操作定义**：核心里的每个构造都必须有对应的**检测器**，即能从几何（或几何加上已识别的规律）把它识别出来。`def`、`mirror`、`repeat` 可逆，是因为“同型、对称、重复”都可以检测；`rand` 不可逆，因为没有检测器。
3. **关系优先，坐标只是残差**：位置由一条主关系加上 align 和少量偏移来表达；表达不了的部分退为 `at=` / `offset=`，并作为质量指标（**坐标依赖率**）来压低。
4. **压缩即理解（MDL）**：对称、重复、同型、集合、变量都是缩短描述的手段。逆向时用“描述是否变短”来决定是否采用某个压缩构造。描述长度应随结构复杂度增长，而不是随物体数量增长。
5. **几何客观，语义由使用者定义并且分层**：语言里只有几何词；concept / pattern 是使用者自己的词汇，可以有层级。
6. **语义层只读几何，不驱动外包络**：关系谓词只在求解之后可用；变体和风格只填充外包络。这是避免循环、保证两遍编译正确的根本不变量。
7. **非破坏编辑 = 分层的“意见”**：可重新生成的基础描述，和人写的修改层，是两个不同的文件。后面的层覆盖前面的层，按路径或集合寻址，路径必须稳定。
8. **诚实的近似**：每条空间事实带容差和实测间隙；每个拟合出的部件带拟合残差和来源；“低置信度”本身就是一个可以查询的集合。
9. **核心小，能力靠组合**：新机制必须是通用的，对任意集合、任意类型都成立，不为某一类场景做特化。

## 2. 精简

| 项 | 决定 | 理由 | 迁移 |
|---|---|---|---|
| `rand / uniform / choose / let seed` | 删除 | 没有检测器；重建时每个物体的位置本来就是确定的 | semantics 示例里的树林改为显式网格；删除对应测试和 README 章节 |
| `if / else if / else`、`if()`、`%` | 删除，用类型派生替代 | “两层以上才有烟囱”本质上是“派生类型多了一个部件”，这可以检测；而分支不能 | 改成 `def house2 : house(floors=2) { box chimney … }` |
| `repeat over=集合` | 删除，由 `over S { … }` 取代 | 它的本质是“给集合的每个成员加部件”，这正是编辑层的通用操作 | 示例和测试改写 |
| `style` / `variant` | 保留写法，内部统一为“意见”机制 | 它们就是“对集合的外观覆盖”，与风格化直接相关 | 行为不变 |
| `tag()` 函数 | 删除 | 与 `#tag` 重复 | — |
| 材质参数、`pipe`、`union / intersect` | 保留 | 代价低；材质名是逆向时最强的分割线索 | — |
| 其余（基本体、span、sweep、曲线、关系、朝向、mirror/rotate、repeat、def、let、集合、concept、pattern、check） | 保留 | 都有检测器，或者是显式的语义声明 | — |

不做（及理由）：多重约束求解、随机散布与避让、由关系决定任意实体的尺寸。这些都是生成侧的问题。

## 3. 强化

### 3.1 重写空间事实（最优先）
- 每一对物体只输出最强的一条关系（on > against > inside > touching）。
- `touching` 改为真实接触：用有向包围盒（OBB）的分离轴测试，不再用世界包围盒。
- 每条事实带上 `{eps, gap, approx}`。
- 先用世界包围盒做 sort-and-sweep 粗筛，取代现在的双重循环。
- 验收：旋转物体只出 on 不出 touching；spaceport 的近似事实少于 20 条；rotation 编译时间少于 200 ms。

### 3.2 `mesh` 叶子节点
```
mesh statue src="base.glb" node="Statue_01" bounds=(-1,0,-1),(1,2,1) ~fit=0.62
```
- 原点规约为包围盒底面中心，和基本体一致。`bounds` 显式写在源码里，所以编译过程仍是纯函数，`on / against / mirror / repeat` 都可以用。
- 渲染器按 `src#node` 异步加载，加载完成前先画线框盒。

### 3.3 元数据通道 `~key=value`
- 可以写在任意语句上，例如 `~fit=0.93 ~err=0.04 ~src=node_117`。它不参与几何，但在 `where` 里可以读取（`all() where fit < 0.8`），会输出到结果里，预览器也会显示。
- 用途：表达误差、置信度、来源；“低置信度部件”因此成为普通集合，可以 style，也可以 check。

### 3.4 `repeat` 继承参照物的朝向
- 计算 on / against 等关系带来的基准朝向；`turn` 在 repeat 上仍然表示“每个实例的增量”。

### 3.5 曲面锚点
- `tank.side[90,0.3]`：圆柱、圆锥、revolve 的侧面（θ 角，高度比例）。`ball.surface[θ,φ]`：球面。
- 锚点的法线取径向。`against` 的条件从“锚点必须是数组”放宽为“锚点有法线”。

### 3.6 地形与网格表面取点（后期）
- 当参照物是 `mesh` 时，`on=terrain[u,1,w]` 用竖直射线采样表面，而不是取包围盒顶面。网格数据作为编译的可选输入；没有数据时退化为包围盒并给出警告。

### 3.7 分层摘要（这是工具，不是语言的一部分）
- `bin/s3d.mjs --outline 2`：按 group 树输出到指定深度，每行包括路径、类型或模板、尺寸、子物体数、概念、主关系。这是 AI 阅读万级物体场景的入口。

### 3.8 事实提供者注册表
- 把关系的固定表改成 provider 列表。第一个 provider 是接触关系（3.1）；以后再加 `walkable()`、`reach(S)`、`sees(S)`。机制本身是通用的，玩法事实只是其中的几个 provider。

### 3.9 稳定命名
- 编译器对匿名实体给出警告；逆向输出必须全部命名。

## 4. 继承与派生：统一设计

目标：用**一个意见机制**加**一个类型派生机制**，把 def、mirror/rotate 副本、style、variant、repeat over，以及以后的编辑层和风格层都收进来。

### 4.1 意见：`over` 与 `drop`
```
over <选择器> [key=value …] [{ over … | drop … | 新语句 … }]
drop <选择器>
```
- 选择器可以是路径、`#tag`、`kind()`、集合运算或概念名。
- 块内的 `over` / `drop` 相对每个成员解析；块内的新语句成为每个成员的子物体，`it` 指向该成员。
- 强度规则：后写的覆盖先写的，`drop` 强于 `over`。
- **两类意见，两个时机**（由原则 6 直接推出）：
  - 改几何、定位或结构的意见：在求解前应用，选择器只能是与事实无关的（路径、标签、kind、静态的 where）。
  - 只改外观的意见（`mat` / `color` / `use=`）：在求解后应用，选择器可以依赖空间事实和概念，也就是现在 style / variant 的做法。
- `style S mat=…` 等价于 `over S mat=…`；`variant S use=T` 等价于 `over S use=T`。
- 对副本（mirror / rotate 生成的）下意见会报错：副本跟随原物体，要么覆盖原物体，要么改用 `copy`。

### 4.2 类型派生：`def B : A(默认值…) { … }`
```
def house(w=7, floors=1) { box body …; wedge half …; box door … }
def tall_house : house(floors=3) {
  over body size=w,4*floors,w*0.8 mat=brick     // 覆盖继承来的部件
  drop door                                      // 删除部件
  box chimney size=0.8,3,0.8 on=body             // 新增部件
}
```
- 参数是基类参数和自身参数的并集，默认值以派生类为准。
- `kind(house)` 是 is-a 关系，会包含 `tall_house` 的实例；`where type == house` 取精确类型。
- 在编辑层里写同名派生 `def house : house { … }`，表示**就地扩展这个类型**，所有实例随之改变。
- 逆向时的对应规则：子树完全相同 → `def`；大部分相同、只有少数部件增删 → `def B : A`；只是尺寸不同 → 参数化。

### 4.3 实例派生：`copy`，以及它和 mirror / rotate 的统一
- `mirror` / `rotate of=` 是**变换派生**：副本共享原物体求解后的变换，精确跟随，不允许覆盖。
- `copy R of=A on=… { over … drop … 新语句 }` 是**结构派生**：把 A 当作一个匿名模板，在 R 下重新展开，然后应用覆盖。它和 4.2 走同一条代码路径。
- 逆向时：刚体变换下完全一致 → `mirror / rotate / repeat / copy`；有少量差异 → `copy { over }`；差异很多 → `def`。具体选哪个由 MDL 决定。

### 4.4 概念层级：`concept B : A = 条件`
- `concept double_door : door = where w > 1.6` 是 `door where w > 1.6` 的简写。编译器记录父概念、输出分类树；如果 B 是独立定义的，则自动检查“B − A 为空”。

### 4.5 层：`import "base.s3d"`
- 编辑层的第一行写 `import "base.s3d"`，可以有多个，按顺序排列，后面的优先。
- 冲突规则：同一路径的同一属性，后面的层胜出；`drop` 胜过 `over`。每个节点记录它受到了哪些意见影响，预览器可以显示来源。
- **路径稳定性**由逆向发射器负责：优先使用 glTF 节点名；其余按“语义名_序号”按空间顺序命名；维护一个 `names.json`（内容指纹 → 名字），重跑逆向时按 OBB IoU 匹配回旧名字；编辑层也可以按 `~src` 元数据寻址，完全不依赖路径。

### 4.6 风格化
- **风格就是一个只包含外观意见的层**：材质定义、`style / over` 的 mat 与 color、`variant / over` 的 `use=模板`，加上为变体准备的派生模板。外包络不变，所以空间关系不变。
- 包含几何意见的层是“编辑层”，不是“风格层”。
- `variant` 不允许改变外包络。要改尺寸，就用 `def B : A` 或 `over … size=`，那属于编辑，会触发重新求解。

## 5. 逆向管线

**输入**：glTF / GLB，用 `@gltf-transform/core` 读取（纯 JS，在 Node 里可用）。

1. **部件拆分**，分三级：
   - L0：按 glTF 节点拆，保留名字和层级。
   - L1：每个 mesh 内按顶点连通分量拆。
   - L2：合批网格的平面区域生长。这一级是真正的难点，可以选用一个 Python 预处理器（trimesh / open3d）输出 `parts.json`。
2. **基本体拟合**：用 PCA 求 OBB，并尽量吸附到 90° 的整数倍。候选类型有 box / cyl / sphere / cone / wedge / revolve / span（杆或梁）/ steps。按覆盖率和体积比打分，分数太低就保留为 `mesh` 叶子。拟合残差写进 `~fit`。
3. **关系提取**：复用编译器本身。先把拟合结果发射成全部用 `at=` 定位的源码，编译得到事实；再按支撑链自下而上，给每个物体选一条主关系；`align` 由共面检测得出；剩下的残差写成 `offset=`。
4. **对称与重复**：按（种类，尺寸容差）聚类，然后识别等差排列（→ `repeat`）、绕轴等角（→ `rotate`）、沿弧线或螺旋等弧长（→ `repeat along`）、镜像面（→ `mirror`）、子树指纹（→ `def` / `def B : A` / `copy`）。是否采用，看发射出来的语句是否变少。
5. **语义识别**：用一个通用的概念库 `lib/semantics.s3d` 来识别；同时让 AI 参与：把摘要和事实交给模型，让它提出 concept / pattern 的定义，再由编译器用 `check` 验证。
6. **输出**：材质放在最前面；物体按支撑顺序排列；全部命名；每个物体带 `~fit ~src`；另外输出 `names.json` 和 `report.json`。

## 6. 闭环评测

- **数据**：`bin/export.mjs` 在 Node 里把示例导出为 GLB，分三个难度：L0 保留名字和逐件 mesh；L1 抹掉名字并打乱顺序；L2 按材质合并 mesh。以后再加入公开的 CC0 模型。
- **指标**（`bin/eval.mjs`，先用 OBB IoU 把两边的对象一一匹配）：
  - 几何：种类正确率、包围盒 IoU、位姿误差。
  - 关系：事实集合的 F1。注意：全部用 `at=` 的朴素基线在这项上也会得高分，所以它衡量的是几何保真度，不是描述质量。
  - 描述质量：**坐标依赖率**、语句数比、`repeat / mirror / rotate / def` 的召回率与精度。
  - 语义：同一个概念库在两边识别出的成员的 F1。
  - 置信度校准：`~fit` 与实际 IoU 之间的相关性。
- **基线**：朴素发射器，即每个部件一个 box、全部用 `at=` 定位。

## 8. 风险

- L2 合批网格的分割是研究性难题，可能需要 Python 工具链。计划把它隔离在阶段 5，前面的阶段都不依赖它。
- OBB 分离轴测试和模式搜索在万级物体上的性能，需要空间索引，并按 group 分块处理。
- 层机制与 variant 两遍编译的交互：外观意见必须严格在求解之后应用。
- 路径稳定性取决于发射器的命名策略，必须在阶段 1 就定下来。
- 真实游戏资产涉及法律和格式问题，所以评测先用自己导出的 GLB 和 CC0 模型。

## 审阅意见（主会话）

- **已核实**：事实重复与噪声（spaceport 158 条中 101 条近似，rotation 969 条中 708 条，编译 556 ms）；`repeat` 的朝向直接返回单位矩阵。计划所依据的代码判断属实。近似 touching 的缺陷是上一轮引入的。
- **调整一处顺序**：建议把第 2 节的“删除”提前到阶段 1 之前，和修复事实一起做。删除的代价很小，先缩小语言表面，可以避免后面的逆向发射器、评测和文档对着即将删除的特性开发。派生和层机制（4.1–4.5）仍然放在阶段 2。
- **工期**：表中的周数只表示相对规模，不是实际工期。
- **依赖**：项目目前零依赖；逆向和导出工具引入 `@gltf-transform/core` 是合理的，但只放在 `bin/` 工具链里，核心编译器 `src/s3d.js` 保持零依赖。

执行中做出的、偏离原计划的决定：
- 关系选择除 on / against 外，加入“相对某个相关物体的锚点”（`at=B[u,v,w]`）：相交、接触的物体不必退回世界坐标。它比 on 弱，但随参照物移动；评测里单独统计为“相对锚点”。
- 校验一律比较几何中心而不是原点：原点是包围盒底面中心，取决于局部 y 轴选了哪一头，对旋转对称的形状和翻转过的盒子都不可靠。
- 编译输出增加按真实形状求的紧包围盒（`nodes[].tight`），评测用它做匹配。

- 稳定命名不另建 names.json：上一次的逆向结果本身就记录了名字，按种类与包围盒 IoU 贪心配对即可，少一种文件格式。
- 镜像召回改为不分方向（副本与它的来源都算处在镜像关系里）：L1 打乱顺序后逆向可能把另一侧当原件，旧口径会把它算成没找回（spaceport L1 从 3/24 变为 48/48）。编译输出的节点新增 `of`（副本的来源路径）。
- 语义库的概念不按形状种类划分（box / span / mesh 都可能是梁）：同一物体在源描述和逆向结果里形状种类可能不同，按种类定义会让理解随写法变化。

- 阵列的例外（完成）：缺成员的阵列写成 `repeat … { }` + `drop 阵列.k`。常规检测之后按格点（直线、x/z 网格）拟合剩下的物体，可以整个吸收已认出的完整阵列；是否接受按描述长度判断（repeat + 部件 + drop 的句数要少于原来的写法），否则三个同样的物体都能凑成“2×2 缺一角”。spaceport_edit 阵列召回 91/97 → 97/97；稳定命名 25/25，阶段 4 的验收标准达到。

- 沿曲线的阵列（完成）：剩下的同形物体按互为最近邻排成链（不要求等间距——等间距的是曲线上的点，侧向偏移的成员在弯道内外间距可差一倍），再用 LM 拟合 Catmull-Rom 控制点与成员在实例坐标系里的偏移，控制点数从少到多试。两个关键：沿切线的偏移与起点相位等价，只解法向、侧向偏移；闭合曲线的第 0 个实例必须落在第 0 个控制点上，拟合时让相位自由、拟合后循环移位归零，接缝处切线不连续，方向反了就在反方向上再解一次。同一条水平曲线上的几组合并成多部件的 `repeat along`，曲线放到成员最低点。rotation 示例：过山车 110 根枕木精确恢复出原来的 9 个控制点，阵列召回 57.7% → 93.5%，语句数比 3.64 → 1.75。
- 部分圆弧的旋转阵列（完成）：环检测改为在垂直于轴的平面里拟合圆心，不要求绕满一圈（至少 4 个成员、角步长 ≥ 2°）。curves 示例 300° 弧上的路灯写成 `rotate lamps n=10 angle=30`，阵列召回 82.4% → 100%。代价：x=0 面上原来靠巧合配对的路灯凑够门槛的水塔镜像不再成立（单独一对镜像不缩短描述）。
