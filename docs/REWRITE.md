# SVG3D 重写计划（新项目，从零开始）

> 日期：2026-10-11 起草，2026-10-12 按对抗审查修订（见文末「审查记录」）。本计划整理自主会话与用户的讨论：语言哲学与 SVG 的对照、原型暴露的原则偏离、性能与渲染路线、人与 AI 协作的“意图”机制。新项目在同级目录 `../svg3d2` 新建（项目名仍为 SVG3D），不继承旧仓库的代码；继承的是语言、原则、测试语料与经验。
>
> 本文是计划，不是规范。语言规范（第 3 节的 `spec/`）是新项目的第一个交付物。

---

## 0. 为什么重写，带走什么，丢掉什么

原型（本仓库）两天半长到约 1.4 万行，在 3.2 万个部件的真实地图上跑通了“逆向 → 评分 → 细化 → 导出 Roblox”，证明了方向。暴露的问题：

1. **原则在实践里松动**：分数从 MDL 变成一组硬规则（实心块按无穷大、散块 1.25 倍、小场景不舍 1 m 以上的块……），都是在三个工程上调出来的；可编辑性不在目标函数里，粗档位下逆向主动写坐标；工具里按英文词表猜角色。
2. **性能**：整张图逆向 10 分钟（16 块并行、预算截断后；同代码单进程 57 分钟）、评分 7 分钟、预览打开 20 秒；worker 并行扩展性差（串行 58 s，4 线程 48 s，8 线程不再变快），是 GC 与内存争用；网格 CSG 一块楼板 3 分钟。
3. **渲染表示错位**：语言是基本体 + 关系 + 布尔，渲染却先三角化再走网格 CSG；界面几何与逆向几何是两套代码。
4. **协作一直没做**：人与 AI 的交互只有“选中 + 留言 + 提议”，人说的话没有被结构化地保存、没有在重跑时被读取。
5. **工具方言渗进语言**：决定层是一种长得像语言、却不经编译器的方言（`def house ~src=[…]` 无体、`~lock` 只有工具认识）；PLAN2 第 11 个待决事项“M1 开工前定下来”一直没定。

**带走**：

- 语言本身（语法、求解语义、空间事实、派生与层）与 9 条原则，只做修订，不推倒。
- 测试语料：`examples/*.s3d`、`out/` 的 L0/L1/L2 导出、`work/dorm`、`work/h1`、`work/sc`（不进 git，单独拷）、`experiments/E1–E3` 的报告。
- **参考输出包**（M0 冻结前由原型导出，见第 9 节）：每个 examples 与 work 场景的编译 JSON（逐物体变换、包围盒、事实）、`out/*.s3d` 的 eval 结果、三个工程的 `score.json`、`compare` 结果与 g10 渲染图。新项目的 M1 到 M3 验收都对着它比。
- 真值评测的指标定义（`bin/eval.mjs`）与校准序（全网格 > 全坐标 > 逆向 > 原文）。
- agent 的命令表（`docs/agent.md`）：命令名、参数、JSON 输出的形状尽量不变，AI 侧的工作流可以直接迁移；逐条迁移对照见第 2.1 节。
- 逆向的经验：PLAN2 的 D1–D11 每条“做法 / 排除 / 效果”，作为检测器的设计输入。

**丢掉**：

- 所有 JS 实现（编译器、逆向、评分、光栅器、CSG、MCP）。
- 工具里的语义启发式：角色词表、名字清理规则、旁路表列推断、白模体积按默认名判定。
- 墙钟预算、`toFixed` 去重、工具与编译器两套包围盒这类打补丁的产物。
- 决定层的语句方言：决定改为意图文件里的结构化字段（第 4 节）。
- 逐字节兼容旧输出的要求：新项目是语言的第二个版本，用参考输出包、真值评测与分数校准序验收，不和旧逆向结果逐字对比。

## 1. 原则（修订版）

沿用原型的 1–7、9 与 PLAN2 的 10–14（描述而非生成、可逆性的操作定义、关系优先、MDL、几何客观语义分层、语义层只读几何、非破坏分层、核心小靠组合、人与 AI 同一套工具、确定可复现、AI 以提议出现、分数是目标函数、不为场景特化）。修订与新增：

- **8 改写，诚实的近似**：诚实不再靠“拟合不了就引用网格”，而是每个物体带拟合度、体积误差与来源；网格引用是一种候选写法，按真实信息量计价，不是兜底。
- **15 语义归 AI，工具只给事实**：工具产出可量化的事实（三角形数、薄度、包含关系、名字分词、材质名、与别的部件的接触），不做“这是灯 / 这是挡墙”的判断。判断由 AI（或人）做成规则或决定，写进工程，工具确定地执行。**没有任何意图时的默认行为必须有定义**（第 5 节末）。
- **16 可编辑性进目标函数**：分数里有“坐标依赖”一项（定义见第 6 节），逆向在描述长度相近时偏向关系。
- **17 硬规则必须有名字和理由**：分数之外的约束（实心块、不舍大块……）作为显式的、可关的**过滤器**存在（被否的候选进报告，不是“记成无穷大后强制搜索”），每条写明针对什么失败案例；所有候选都被否时发射现有最好的写法并标记。校准必须包含三个实战工程之外的数据。
- **18 确定性按工作量，范围有声明**：预算以几何内核里可确定计数的操作量计（板件 = 三角形数 × 格子数，评分 = 采样点数 × BVH 访问节点数，阵列 = 候选对数），不是候选个数、更不是墙钟；额度按部件或类型分配，是该部件事实（三角形数、尺寸、角色）的固定函数，**没有全局共享池**，所以与线程数、领活顺序无关；超额的部件带 `~budget=` 标记并进报告。逐字相同的承诺只覆盖 compile / facts / reverse / score / compare 的数值输出；render 的 PNG 只承诺几何正确，不承诺跨 GPU 逐位相同。落地清单见第 2 节。
- **19 同一份数学定义，两份实现**：几何内核（Rust）与渲染（WGSL）按规范第 3.2 条的同一份 SDF / 求交定义写，差异由离屏渲染与 CPU 采样的对拍测试封顶。GPU 不经三角化直接画基本体与布尔。

## 2. 架构：分层与仓库布局

```
svg3d2/            （与本仓库同级：../svg3d2；项目名仍叫 SVG3D）
  spec/            语言规范（Markdown）：语法、求解语义、事实、层、元数据；版本号
  crates/
    s3d-geom       几何内核：基本体（SDF、射线求交、包围盒、采样）、三角网格 BVH 最近点（parry3d）、凸块 SAT（自写）、
                   容差简化凸包（自写，≤ 24 点）、非封闭网格的体积与内外近似（自写）、平面聚类、多边形、CPU 软件光栅（compare 用）
    s3d-lang       编译器：解析 → 展开 → 派生与修改 → 求解 → 事实 → 语义
    s3d-score      自评分数（描述长度、网格计价、双向残差、体积误差、坐标依赖；增量）+ 真值评测（原 eval.mjs）
    s3d-reverse    逆向：部件读取（含决定的执行）、检测器流水线、候选筛选、子集逆向（refine / detect 的底层）、稳定命名、分块
    s3d-render     渲染：wgpu，基本体实例化直绘；无头（PNG）与 WebGPU 共用 WGSL
    s3d-project    工程目录、层、意图（读写、重绑、生命周期）、提议、日志
    s3d-tool       命令表（一张表，三种外壳：CLI、MCP、HTTP）；crop、sidecar、unit 猜测也在这里
    s3d-export     GLB、Roblox
  web/             界面：TypeScript + Vite，薄；加载 wasm
  corpus/          examples、L0/L1/L2 导出、真值评测、参考输出包、校准基线、external/<名>/（带 SOURCES.md）、intents/（样本意图）
  docs/            agent 手册、计划、进展
```

**wasm 目标**：`s3d-geom`、`s3d-lang`、`s3d-score`、`s3d-reverse`、`s3d-render` 都出 wasm（浏览器里编译、渲染、逆向、评分）；`s3d-project`、`s3d-tool`、`s3d-export` 只出 native，界面经 HTTP 外壳读写工程、处理提议。

依赖取舍：

| 需求 | 用 | 说明 |
|---|---|---|
| 线性代数 | glam（与 parry3d 0.31 的 glamx 同源） | 开 `libm` + `scalar-math`，关 fast-math 与 FMA；不选 nalgebra |
| 三角网格 BVH、点到网格最近点、射线求交、精确凸包、凸体 GJK/EPA 距离 | parry3d | 开 `enhanced-determinism`，不开 simd。**它没有**任意凸多面体之间的通用 SAT（只有 cuboid 等特例）、没有容差简化凸包、带符号距离要封闭有向网格；这三样 s3d-geom 自己写并带测试 |
| 多边形三角化 | earcut | — |
| GLB 读写 | gltf | — |
| 渲染 | wgpu + WGSL | 不直接写 Vulkan；原生设备只用 `Features::all_webgpu_mask()` 里的特性与 WebGPU 默认 Limits，无头与浏览器才真能共用一份 WGSL |
| wasm | wasm-bindgen；wasm-bindgen-rayon（可选，见决定 9） | wasm 目标不开 `+simd128` |
| 解析 | 手写递归下降 | 语法小，错误信息要好，不上 parser generator |

**原则 18 的落地清单**（进 CI）：全项目禁用 std 的 sin / cos / exp / pow / hypot / atan2（clippy `disallowed_methods`），统一走 libm，native 与 wasm 同一份；并行只允许“静态分块 + 按块号顺序归约”，不允许 `par_iter` 直接做浮点 sum / min；容器用 BTreeMap / IndexMap / 排序过的 Vec，禁止迭代 HashMap；分块按估计工作量平衡，不按部件数。

`s3d-lang` 保持少依赖（只依赖 `s3d-geom`），语言不绑渲染与逆向。

## 3. 语言规范（M0 的交付物）

规范先于代码。内容：

1. **词法与语法**（EBNF）；语句、属性、表达式、选择器。元数据 `~k=v` 对**所有**语句合法（含 over / drop / concept / pattern / check / style / variant / def / let / import），不参与几何与语义求值，仅供追溯与 `where` 读取。规则型选择器不引入新符号：`where` 里增加 `name ~ /正则/`、`src ~ /正则/`、`mat == …` 谓词。**路径与命名**小节：路径段的构造规则（具名、匿名 `kind#i`、阵列 `i`、副本 `mirrored` / `rk`）、名字解析顺序与歧义规则、匿名容器的穿透、import 后重名的处理、保留标识符清单；`kind` / `name` / `#` 的取值规则，消除 `#` 既是标签又可能是颜色的双义；找不到的名字报错而不是退化成字符串。
2. **实体与曲线的几何定义**：原点约定（底面中心）、局部坐标系、每种实体的 SDF / 射线求交 / 包围盒 / 表面采样的数学定义。这是几何内核与渲染共用的依据。布尔的操作数种类与嵌套规则在这里定（哪些实体有 SDF、含三角化路径实体的布尔整组走三角化）。
3. **定位与朝向的求解语义**：关系的优先级、锚点、align / gap / offset、继承朝向的规则、依赖排序与后置；容器的定位按包络。
4. **派生与修改**：def、派生、copy、mirror / rotate 副本与孪生体、over / drop 的两个时机。**保名换形展开为可判定的表**：目标种类 × 原种类 → 保留的属性集（定位与朝向 / 外观 / 模板参数 / 标签与元数据 / 子语句）；容器 → 容器时原子语句的去向（建议丢弃，要保留须显式写）；模板 → 模板只在派生链上保留参数，否则按名字匹配、多余的报错；重建型修改与就地修改的区别及其对后续 over 的影响；副本上的限制。
5. **层**：import 的顺序与冲突规则；外观层（style / variant / 只改外观的 over）可以用事实与概念做选择器，几何层不能。
6. **空间事实**：每种关系的精确定义、容差、提供者接口；凸块之间的分离量按原型 `partGap` 的定义（面法线 + 边叉积 + 球心方向，取最大分离量，可为负）写进规范。
7. **语义层**：concept / pattern / check / style / variant 的求值次序与可见性。求值分两阶段：阶段一（几何 + 事实 + 语义）决定变体与样式的选择集，阶段二只替换外观、不改任何包围盒与事实；变体对语义层、事实、选择器不可见的保证；变体模板与外包络的接口（`w/h/d` 自动传参、定位到外包络底面中心）；style 与节点自身 `mat=` / `color=` 的优先级。
8. **元数据**：规范只定义 `~k=v` 的语法、“不参与几何”与“可在 where 里读”两条保证，**不保留任何键名**。`~src ~fit ~role ~intent ~lock ~scatter ~budget` 这类键是工具约定，整表写在 `docs/agent.md`。
9. **兼容性声明**：语法**向后兼容**（旧文件全部可编译），列出新增项（元数据对所有语句合法、where 的正则谓词、`~lang=2` 文件头）与行为变化清单（块内 `material` 由静默忽略改为报错、容器 → 容器换形的子语句规则等），每条带原型行为与新行为。
10. **材质与外观**：`material` 的合法位置（限最外层，块内写报错）、属性集、同名覆盖规则、`default=true` 的唯一性、继承顺序（style > color > mat > 父级 > default > 内置）、副本 / copy / 变体的材质来源。

规范里**不**出现：档位、分数、角色、决定的写法。这些是工具约定，写在 `docs/agent.md`。

## 4. 人与 AI 协作：意图（intent）

### 4.1 目标

人在逆向或正向建模时选中一些对象或一个区域，用自然语言说需求（“这一片是食堂，桌椅是同一种”“这栋楼是空心的，三层”“这些是挡墙，不要画出来”“把这一排路灯换成矮的”）。这段话是人对场景的先验，作用是**降低这部分物体的熵**：逆向少猜、正向少编。它必须被保存下来，以后再次逆向或重建时被读取，而不是只影响一次。

原型里已有的三个碎片，`decisions.s3d`（逆向约束）、`note / inbox`（留言）、`state/selection.json`（选中），加上 `roles.json`，合并成一个机制。

### 4.2 一条意图是什么

```
intents/NNN.json
{
  "id": 17,
  "created": "2026-10-11T20:14:00Z",
  "author": "human" | "ai",
  "status": { "state": "proposed" | "accepted" | "retired", … },   // author=ai 的意图在被人接受前是 proposed，重跑时不读
  "selection": {                       // 锚定（见 4.3），多种锚并存
    "paths":   ["dorm_02", "dorm_02.*"],
    "sources": ["Dormitory_02_ExterWall_01", "Dormitory_02_InterWall_01@2"],
    "region":  { "box": [x0,y0,z0,x1,y1,z1], "unit": "scene" },
    "fingerprints": [ { "kind": "box", "size": [..], "center": [..] } ]
  },
  "text": "这栋楼是空心的宿舍楼，三层，外墙是板件，里面的床是同一种",
  "formal": {
    "decisions": [                     // 结构化字段，由 s3d-reverse 读取，不是语句（词汇表见 4.2.1）
      { "op": "hollow", "floors": 3 },
      { "op": "type", "name": "bed", "sources": ["Bed_01", "Bed_01@2", "Bed_01@3"] }
    ],
    "semantics": ["concept dorm_bed = kind(bed) & inside(dorm_02)"],       // 语句，进 semantics.s3d
    "edits":     [],                                                      // 语句，进 edits.s3d
    "checks":    ["check \"三层楼板\" count(slab & inside(dorm_02)) == 3"], // 语句，进 semantics.s3d
    "unformalized": "外墙是板件"        // 没能形式化的部分，原文保留，作为 AI 下次的提示
  },
  "status": {
    "bound": { "paths": 2, "sources": 2, "fingerprints": 0, "suspicious": 0 },
    "satisfied": true,
    "conflicts": [],                                   // 与别的意图在同一部件 / 同一键上赋了不同值
    "effect": { "atAccept": { "delta": -811, "changed": 14 } }   // accept 时 preview 给的分数变化，永久保存
  },
  "history": [ { "when": "…", "event": "rebound | unsatisfied | retired | conflict", "blamed": [23], "why": "…" } ]
}
```

要点：

- **原文永远保留**。形式化是 AI 的翻译，可能不完整、可能过时；下次 AI 读意图时同时读原文与形式化结果，可以重新翻译。
- **两类形式化产物，两条执行路径**：`decisions` 是结构化字段，由 s3d-reverse 在读取部件阶段或逆向阶段执行，不经编译器；`edits / semantics / checks` 是编译器能执行的语句，接受后进各自的层，每条带 `~intent=17`，所以每条语句都能追溯到人说的哪句话，反过来按意图号能找到它生成的全部语句。
- **checks 是意图的验收**：意图不只是输入，也是测试。重跑后 `check` 不过，意图状态变成 unsatisfied；用 violators 的 `~intent` 反查最近一次改动这些物体的意图，写进 history 的 `blamed`，不把账记错人。
- **effect 让人看到价值**：accept 时记下 preview 的分数变化（永久保存为 `atAccept`）；重跑后不自动重算，`intent effect N` 按需做留一法（不带它在它的区域里用邻域评分重跑）。effect 里分开报“被排除出计分的部件数 / 网格面积”与“分数变化”，界面上不把前者当成压缩。正向意图的 effect 只报 checks 通过数与描述长度。

#### 4.2.1 决定的词汇表

决定只能是下表里的操作；不在表里的键，`intent add` / `accept` 拒绝，不是忽略。

| 作用阶段 | 操作 | 选择器 | 含义 |
|---|---|---|---|
| 读取部件（分块之前，按源部件） | `drop` | sources / rule | 这个部件是噪声，忽略 |
| | `role` | sources / rule | 角色（structure / decor / terrain / decal / collision / helper）；角色的取值表在 agent.md |
| | `merge` | sources | 这几个部件是一个物体，可带 `name` 与 `shape` |
| | `type` | sources / rule | 这几个部件是同一类型 |
| | `keep-mesh` | sources | 保留为网格引用 |
| | `shape` | sources | 指定形状种类（box / cyl / …） |
| 逆向（按物体） | `hollow` | paths | 空心，可带 `floors` |
| | `tol` | paths / region | 局部容差 |
| | `lock` | paths | 沿用上一次的定位 / 形状 / 整行（按物体，不是按整份 base） |
| | `array` / `mirror` | paths | 指定阵列或镜像（原型未支持，M3 实现） |

`rule` 选择器是源部件谓词（名字、材质、旁路表列的正则），只在读取部件阶段求值，产物是源侧事实（如 `state/source-roles.json`），不写成 `over`。

### 4.3 锚定与重绑

选择必须在源模型改版、重跑逆向、名字变化之后还能找回来。四种锚：

1. **路径**：稳定命名保证的；最直接，但名字会变。
2. **来源**：`~src` 的源部件 id（节点名、`名字@k`）；源模型不换时最稳。路径与来源常常来自同一个节点名，美术改名时同时失效，不是独立后备。
3. **几何指纹**：形状种类 + 尺寸 + 世界位置（容差按档位）；源模型改版后按 IoU 重绑。
4. **区域**：世界坐标盒或多边形柱体；最弱，但对“这一片是食堂”这类意图恰恰是对的锚：区域里的东西换了，意图仍然成立。

重绑规则：**路径命中后必须用指纹或来源交叉验证**（同种类且 IoU 过阈值，或 `~src` 一致）才算 bound；只有路径命中、指纹不符的记为 `suspicious`，不算 bound。配套要求：稳定命名的编号**永不回收**（已释放的名字进墓碑表，名字记忆跨多轮）；种类变化（box → group、box → subtract）时按 IoU 继续沿用名字。重绑是工具的确定性操作（`intent rebind`），结果写回 status；绑不上的列为 dangling，由人或 AI 处理，不静默丢弃。稳定命名与指纹锚共用同一个重绑函数。路径的比较基于规范 3.1 的构造规则，不是字符串。

### 4.4 流程

```
人：选中对象 / 框选区域 ──▶ 说一句话（界面「意图」面板，或 CLI `intent add --selection --text=…`）
                                   │
AI：读意图原文 + 选中物体的 inspect + 渲染图 ──▶ 翻译成 formal（决定 / 语义 / 编辑 / 检查）
                                   │                 以提议的形式出现（propose --intent=17）
人：预览（分数变化、新错误、渲染）──▶ 接受 / 否决（否决理由进意图的 history）
                                   │
工具：接受后语句进层、决定进意图状态；之后每次 reverse / 正向重建：
      1. 读全部 accepted 意图，重绑锚；2. 读取部件阶段执行源侧决定（分块之前）；3. 逆向阶段执行物体决定；
      4. 语义与编辑层照常叠加；5. 跑 checks，报 unsatisfied / dangling / conflict
```

- author=ai 的意图（包括规则型）在被人接受前 state 为 proposed，重跑时不读；无人值守模式下由人预先接受一批，或显式 `--accept-ai-intents`。
- 正向建模走同一条路：没有源模型时，意图就是规格。AI 生成的语句放进按区域分文件的生成层（`gen/<区域>.s3d` + 一行 import）；“按意图重新生成这一块”= 整文件替换，以上一轮生成结果作为稳定命名的名字记忆；重生成后对所有意图跑一次 rebind，悬空的按 4.3 报 dangling。

### 4.5 意图与角色、命名的关系

原则 15 的落地：角色、名字清理这类判断不再是工具内置，而是 AI 在看过样本后写出的**规则型意图**（选择器是源部件谓词，不是具体对象）：

```
{ "author": "ai", "status": { "state": "accepted" },
  "selection": { "rule": { "name": "Blocker|Collision|^Block[A-Z]" } },
  "text": "这些是隐形挡墙",
  "formal": { "decisions": [ { "op": "role", "value": "collision" } ] } }
```

工具按规则确定地执行；换一个美术团队，换的是意图，不是代码。原型的 `roles.json` 就是这种意图的雏形。corpus 里带一份 SpaceCenter 的规则型意图样本（`corpus/intents/roles.spacecenter.json`），标明是样本不是代码，M3 验收用它。

### 4.6 优先级、冲突、撤回

- **优先级**：具体对象意图 > 规则型意图；同类之间按意图 id 新的压旧的（不是层里的行序，所以 retire 再 accept 不改变优先级）。`drop` 不再无条件胜出。
- **冲突**：同一部件 / 同一键被两条意图赋不同值时，记为 conflict 写进两条意图的 status，重跑报告里列出，不静默取其一。
- **撤回**：`intent retire N` 生成一条“撤回全部 `~intent=N` 语句”的提议，走 preview / accept；有编译错误时列出依赖它的意图，要求先处理或级联 retire。意图文件保留，state = retired。
- **不做**：自然语言的本地解析（翻译一律由 AI 做）；意图之间的自动合并；多用户（有 author 字段，没有权限与并发）。

## 5. 逆向的新骨架

```
读取部件（GLB 节点、享元、连通分量；执行源侧决定：drop / role / merge / type / keep-mesh / shape）
   │
分块（部件数超过阈值时；按估计工作量平衡；merge / type 决定涉及的部件强制进同一块或列为跨块任务）
   │  每块：
   │  事实（几何内核）：包围盒、主轴、薄度、体积类事实（实心比例）、平面聚类、连通性、接触对、同网格实例、同形候选
   │  检测器流水线（每个独立、可关，输出候选写法 + 描述长度下界）：
   │     基本体 / 板件 / 外壳-空腔-开口 / 并 / 扫掠 / 旋转体 / 台阶 / 平板 / 凸包 / 小场景（递归，显式上下文）
   │     阵列（平移、旋转、曲线、带例外）/ 镜像 / 类型（享元 → 几何同形）
   │  候选筛选：先按事实与长度下界剪枝，再评局部分数；具名约束作为过滤器；预算按操作量计
   │  输出：带几何与事实的候选 IR（不命名、不发射）
   │
合并 IR → 跨块第二遍：只在“离块边不超过最大阵列间距的候选 + 全场同网格的类型实例”这个子集上跑阵列 / 镜像
   │
关系：编译坐标版 → 事实 → 每物体一条主关系（参照物可以跨块）；坐标依赖项让关系在长度相近时胜出
   │
校验 → 稳定命名（名字记忆、墓碑表）→ 发射（全命名、带 ~src ~fit ~intent ~budget）：全局做一次
```

与原型的差别：候选不是“全生成再比分”，而是事实先缩小集合；每个检测器有自己的测试语料与召回指标；语义判断（角色）从流水线里消失，变成读意图；合并与改名不再是对发射后文本的操作（原型悬空引用与“块边只能写坐标”的根源）。

**没有任何意图时的默认**：逆向不区分角色，所有部件当同一种；受具名约束约束的集合由约束自己的选择器给出，默认空集 = 不约束；compare 比全部部件。

## 6. 评分修订

`S = L_stmt + L_mesh + R_src + R_recon + R_vol + E_edit`

- 前五项沿用原型的定义（铰链、同材质优先、网格按真实信息量、体积误差）。
- `E_edit`：坐标依赖的代价。**坐标依赖的定义基于事实**：一个物体算坐标依赖，当且仅当它的定位没有参照物，或参照物与它之间没有接触类事实（on / against / inside / touching / intersects）。这样“全锚到地面”不会被算成关系。每个坐标依赖的物体付一个固定项（量级相当于一个名字），权重可配置；决定 7 的上界与这个定义绑定。
- 硬规则改为**具名约束**，语义是过滤器：`constraints: { solidFill: {maxWrong: 0.3, minVolume: 8}, keepLargeParts: {minSize: 1.0} }`，每条可关、带选择器（默认空集），报告里列出哪些候选因为哪条约束被否；所有候选都被否时发射现有最好写法并标记。
- 校准集：三个实战工程 + 外部数据（6.1）。校准序（全网格 > 全坐标 > 逆向 > 原文）与真值指标的单调性在 corpus 上成立；外部数据没有“原文”，只验前三项与 compare 的 missing / extra。
- 增量评分从第一天设计进去（原型是后加的），状态跨进程持久化。

### 6.1 外部数据获取

- 候选：用 Kenney / Quaternius 的 CC0 模块套件按其示例场景拼一张 ≥ 2000 部件、有实例结构、节点名带另一套命名习惯的地图；Poly Haven 或 Sketchfab 按 CC0 筛选的 2 个不规则模型；若需要“真值原文”，用新语言手写一个小场景并导出 L0/L1/L2 作为合成基线。
- 入选标准写成数字（部件数、实例结构、命名习惯、是否带碰撞 / 辅助体）；放在 `corpus/external/<名>/`，带 `SOURCES.md`。
- 向用户确认候选清单是 M0 的一项交付；下载每次单独确认。

## 7. 渲染

- **规模**：整张 SpaceCenter 阵列展开后约 10 万个重建物体（原型 `score.json` 的 byRole 合计 102 843；预览器合批前 14.6 万个 Mesh），不是 3.2 万。
- **wgpu + WGSL**，一份着色器：浏览器 WebGPU（界面）、原生无头（agent 的 `render`）。原生设备只用 WebGPU 特性掩码与默认 Limits。**只做 WebGPU，不做 WebGL2 后备**（用户决定，2026-10-12）。
- **基本体实例化直绘**：一个单位立方体的实例化绘制，实例缓冲存种类 + 变换 + 参数；计算着色器做视锥剔除并压实实例表，一次 `draw_indexed_indirect` 画完（浏览器没有 multi-draw indirect）；片元里按种类做解析求交（盒、柱、锥、球、楔、凸包）或距离场步进（旋转体、平板）；`subtract / union / intersect` 在片元里按距离场组合（布尔树编译期展平成后缀序列，固定小栈求值），不做网格 CSG；含三角化路径实体（扫掠、网格引用）的布尔整组走三角化。拾取用 ID 附件，不用 BVH（BVH 是整屏光线遍历的结构，和包围盒光栅化不是一条路线）。
- **代价**：片元写 `frag_depth` 会关掉 early-z，成本与包围盒的屏幕面积总和成正比。给一条 overdraw 预算（1080p 下平均每像素 ≤ 4 次求交），M2 用 SpaceCenter 的 iso / top 两个视角实测。
- **compare 在 CPU 上算**（s3d-geom 的软件光栅或射线采样），它是用户验收的尺子，必须可复现；GPU 版只作为界面里的快速预览。
- 降级方案：预览性能不达标时改为“直绘 + 实例化三角网格混合”。

## 11. 风险

- **规范写不完就想写代码**：M0 是硬门槛，没有规范不开 M1。
- **Rust 的迭代速度**：逆向的启发式迭代会比 JS 慢；用检测器隔离 + corpus 指标自动化来抵消。
- **渲染路线是新的**：基本体实例化直绘 + 片元布尔不是现成库；M2 先做无头版验证正确性，预览性能不达标时降级为“直绘 + 实例化三角网格混合”。
- **确定性**：Rust 标准库的三角函数精度不保证跨平台一致；靠第 2 节的落地清单与三处哈希对拍守住，GPU 输出不进承诺。
- **意图的翻译质量**：AI 翻译错了会以提议出现，人要看得懂预览；effect 与 checks 是防线；E4a 提前到 M4 末给读数。
- **外部数据**：CC0 资产库多是单件道具与模块套件，不是拼好的关卡；按 6.1 自己拼，每次下载单独确认。
