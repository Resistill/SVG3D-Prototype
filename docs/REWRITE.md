# SVG3D 重写计划（新项目，从零开始）

> 日期：2026-10-11。本计划整理自主会话与用户的讨论：语言哲学与 SVG 的对照、原型暴露的原则偏离、性能与渲染路线、人与 AI 协作的“意图”机制。新项目在同级目录新建，不继承旧仓库的代码；继承的是语言、原则、测试语料与经验。
>
> 本文是计划，不是规范。语言规范（第 3 节的 `spec/`）是新项目的第一个交付物。

---

## 0. 为什么重写，带走什么，丢掉什么

原型（本仓库）两天半长到约 1.4 万行，在 3.2 万个部件的真实地图上跑通了“逆向 → 评分 → 细化 → 导出 Roblox”，证明了方向。暴露的问题：

1. **原则在实践里松动**：分数从 MDL 变成一组硬规则（实心块按无穷大、散块 1.25 倍、小场景不舍 1 m 以上的块……），都是在三个工程上调出来的；可编辑性不在目标函数里，粗档位下逆向主动写坐标；工具里按英文词表猜角色。
2. **性能**：整张图逆向 10 分钟（预算截断后）、评分 7 分钟、预览打开 20 秒；worker 并行扩展性差（串行 58 s，4 线程 48 s，8 线程不再变快），是 GC 与内存争用；网格 CSG 一块楼板 3 分钟。
3. **渲染表示错位**：语言是基本体 + 关系 + 布尔，渲染却先三角化再走网格 CSG；界面几何与逆向几何是两套代码。
4. **协作一直没做**：人与 AI 的交互只有“选中 + 留言 + 提议”，人说的话没有被结构化地保存、没有在重跑时被读取。

**带走**：

- 语言本身（语法、求解语义、空间事实、派生与层）与 9 条原则，只做修订，不推倒。
- 测试语料：`examples/*.s3d`、`out/` 的 L0/L1/L2 导出、`work/dorm`、`work/h1`、`work/sc`（不进 git，单独拷）、`experiments/E1–E3` 的报告。
- 真值评测的指标定义（`bin/eval.mjs`）与校准序（全网格 > 全坐标 > 逆向 > 原文）。
- agent 的命令表（`docs/agent.md`）：命令名、参数、JSON 输出的形状尽量不变，AI 侧的工作流可以直接迁移。
- 逆向的经验：PLAN2 的 D1–D11 每条“做法 / 排除 / 效果”，作为检测器的设计输入。

**丢掉**：

- 所有 JS 实现（编译器、逆向、评分、光栅器、CSG、MCP）。
- 工具里的语义启发式：角色词表、名字清理规则、旁路表列推断、白模体积按默认名判定。
- 墙钟预算、`toFixed` 去重、几套不一致的包围盒语义这类打补丁的产物。
- 逐字节兼容旧输出的要求：新项目是语言的第二个版本，用真值评测与分数校准序验收，不和旧逆向结果逐字对比。

## 1. 原则（修订版）

沿用原型的 1–7、9 与 PLAN2 的 10–14（描述而非生成、可逆性的操作定义、关系优先、MDL、几何客观语义分层、语义层只读几何、非破坏分层、核心小靠组合、人与 AI 同一套工具、确定可复现、AI 以提议出现、分数是目标函数、不为场景特化）。修订与新增：

- **8 改写，诚实的近似**：诚实不再靠“拟合不了就引用网格”，而是每个物体带拟合度、体积误差与来源；网格引用是一种候选写法，按真实信息量计价，不是兜底。
- **15 语义归 AI，工具只给事实**：工具产出可量化的事实（三角形数、薄度、包含关系、名字分词、材质名、与别的部件的接触），不做“这是灯 / 这是挡墙”的判断。判断由 AI（或人）做成规则或决定，写进工程，工具确定地执行。
- **16 可编辑性进目标函数**：分数里有“坐标依赖”一项，或至少与分数并列报告；逆向在描述长度相近时偏向关系。
- **17 硬规则必须有名字和理由**：分数之外的约束（实心块、不舍大块……）作为显式的、可关的约束项存在，每条写明针对什么失败案例；校准必须包含三个实战工程之外的数据。
- **18 确定性按工作量**：预算以工作量（候选数、迭代数）计，不以墙钟计；三角函数、随机采样用固定实现；同一输入在任何机器、任何线程数下逐字相同。
- **19 渲染表示 = 编译结果**：GPU 直接画基本体与布尔，不经过三角化；界面、离屏渲染、评分采样用同一个几何内核。

## 2. 架构：分层与仓库布局

```
<新目录>/
  spec/            语言规范（Markdown）：语法、求解语义、事实、层、元数据；版本号
  crates/
    s3d-geom       几何内核：基本体（SDF、射线求交、包围盒、采样）、BVH 最近点、凸块 SAT、凸包、平面聚类、多边形
    s3d-lang       编译器：解析 → 展开 → 派生与修改 → 求解 → 事实 → 语义；native + wasm 两种目标
    s3d-score      自评分数：描述长度、网格计价、双向残差、体积误差、可编辑性；增量
    s3d-reverse    逆向：部件读取、检测器流水线、候选生成、按分数选择、分块
    s3d-render     渲染：wgpu，基本体直绘；无头（PNG）与 WebGPU 共用 WGSL
    s3d-project    工程目录、层、意图、提议、日志
    s3d-tool       命令表（一张表，三种外壳：CLI、MCP、HTTP）
    s3d-export     GLB、Roblox
  web/             界面：TypeScript，薄；加载 s3d-lang 与 s3d-render 的 wasm
  corpus/          examples、L0/L1/L2 导出、真值评测、校准基线
  docs/            agent 手册、计划、进展
```

依赖取舍：

| 需求 | 用 | 说明 |
|---|---|---|
| 线性代数 | nalgebra 或 glam | — |
| BVH、最近点、SAT、凸包 | parry3d | 原型自写的 BVH、凸包、去重都出过问题，不再自己造 |
| 多边形三角化 | earcut | — |
| GLB 读写 | gltf | — |
| 渲染 | wgpu + WGSL | 不直接写 Vulkan；wgpu 封装 Vulkan / Metal / DX12 / WebGPU |
| wasm | wasm-bindgen | — |
| 解析 | 手写递归下降 | 语法小，错误信息要好，不上 parser generator |

`s3d-lang` 保持少依赖（只依赖 `s3d-geom`），语言不绑渲染与逆向。

## 3. 语言规范（M0 的交付物）

规范先于代码。内容：

1. 词法与语法（EBNF）；语句、属性、表达式、选择器、元数据 `~k=v`。
2. 实体与曲线的几何定义：原点约定（底面中心）、局部坐标系、每种实体的 SDF / 射线求交 / 包围盒 / 表面采样的数学定义。这是几何内核与渲染共用的依据。
3. 定位与朝向的求解语义：关系的优先级、锚点、align / gap / offset、继承朝向的规则、依赖排序与后置。
4. 派生与修改：def、派生、copy、mirror / rotate 副本与孪生体、over / drop 的两个时机、保名换形。
5. 层：import 的顺序与冲突规则；哪些层可以改几何、哪些只改外观。
6. 空间事实：每种关系的精确定义、容差、提供者接口。
7. 语义层：concept / pattern / check 的求值；语义层只读几何。
8. 元数据的保留键：`~src ~fit ~role ~intent ~lock ~scatter`，以及“元数据不参与几何”的保证。
9. 兼容性声明：对原型 `.s3d` 的差异清单（预计很小：语法不变，去掉几个工具约定渗进语言的地方）。

规范里**不**出现：档位、分数、角色、决定层的写法。这些是工具约定，写在 `docs/agent.md`。

## 4. 人与 AI 协作：意图（intent）

### 4.1 目标

人在逆向或正向建模时选中一些对象或一个区域，用自然语言说需求（“这一片是食堂，桌椅是同一种”“这栋楼是空心的，三层”“这些是挡墙，不要画出来”“把这一排路灯换成矮的”）。这段话是人对场景的先验，作用是**降低这部分物体的熵**：逆向少猜、正向少编。它必须被保存下来，以后再次逆向或重建时被读取，而不是只影响一次。

原型里已有的三个碎片，`decisions.s3d`（逆向约束）、`note / inbox`（留言）、`state/selection.json`（选中），合并成一个机制。

### 4.2 一条意图是什么

```
intents/NNN.json
{
  "id": 17,
  "created": "2026-10-11T20:14:00Z",
  "author": "human" | "ai",
  "selection": {                       // 锚定（见 4.3），多种锚并存，重绑时按顺序试
    "paths":   ["dorm_02", "dorm_02.*"],
    "sources": ["Dormitory_02_ExterWall_01", "Dormitory_02_InterWall_01@2"],
    "region":  { "box": [x0,y0,z0,x1,y1,z1], "unit": "scene" },
    "fingerprints": [ { "kind": "box", "size": [..], "center": [..] } ]
  },
  "text": "这栋楼是空心的宿舍楼，三层，外墙是板件，里面的床是同一种",
  "formal": {                          // AI 翻译出的形式化部分（可以为空、可以部分）
    "decisions": ["over dorm_02 ~hollow=1 ~floors=3", "def bed ~src=[…]"],
    "semantics": ["concept dorm_bed = kind(bed_type) & inside(dorm_02)"],
    "edits":     [],
    "checks":    ["check \"三层楼板\" count(slab & inside(dorm_02)) == 3"],
    "unformalized": "外墙是板件"        // 没能形式化的部分，原文保留，作为 AI 下次的提示
  },
  "status": {
    "bound": { "paths": 2, "sources": 2, "fingerprints": 0 },   // 最近一次重绑的结果
    "satisfied": true,                                         // checks 是否通过
    "effect": { "scoreBefore": 1241, "scoreAfter": 430 }      // 这条意图在它的区域里降低了多少分
  },
  "history": [ { "when": "…", "event": "rebound | unsatisfied | retired", "why": "…" } ]
}
```

要点：

- **原文永远保留**。形式化是 AI 的翻译，可能不完整、可能过时；下次 AI 读意图时同时读原文与形式化结果，可以重新翻译。
- **形式化的语句进各自的层**，带 `~intent=17`，所以每条语句都能追溯到人说的哪句话；反过来按意图号能找到它生成的全部语句。
- **checks 是意图的验收**：意图不只是输入，也是测试。重跑后 `check` 不过，意图状态变成 unsatisfied，界面与 `score` 都会报。
- **effect 让人看到价值**：这条意图在它的区域里让分数降了多少、让多少物体从坐标变成关系。这就是“降低熵”的度量。

### 4.3 锚定与重绑

选择必须在源模型改版、重跑逆向、名字变化之后还能找回来。四种锚按强到弱：

1. **路径**：稳定命名保证的；最直接，但名字会变。
2. **来源**：`~src` 的源部件 id（节点名、`名字@k`）；源模型不换时最稳。
3. **几何指纹**：形状种类 + 尺寸 + 世界位置（容差按档位）；源模型改版后按 IoU 重绑，原型的稳定命名已经在用这个办法。
4. **区域**：世界坐标盒或多边形柱体；最弱，但对“这一片是食堂”这类意图恰恰是对的锚：区域里的东西换了，意图仍然成立。

重绑是工具的确定性操作（`intent rebind`），结果写回 status；绑不上的列为 dangling，由人或 AI 处理，不静默丢弃。

### 4.4 流程

```
人：选中对象 / 框选区域 ──▶ 说一句话（界面「意图」面板，或 CLI `intent add --selection --text=…`）
                                   │
AI：读意图原文 + 选中物体的 inspect + 渲染图 ──▶ 翻译成 formal（决定 / 语义 / 编辑 / 检查）
                                   │                 以提议的形式出现（propose --intent=17）
人：预览（分数变化、新错误、渲染）──▶ 接受 / 否决（否决理由进意图的 history）
                                   │
工具：接受后语句进层、意图状态更新；之后每次 reverse / 正向重建：
      1. 读全部意图，重绑锚；2. 决定层约束逆向；3. 语义与编辑层照常叠加；
      4. 跑 checks，报 unsatisfied / dangling；5. 把每条意图的 effect 算出来
```

正向建模走同一条路：没有源模型时，意图就是规格；AI 按区域与意图写语句（提议），checks 是验收。“按意图重新生成这一块”是正向侧的 `reverse` 对应物。

### 4.5 意图与角色、命名的关系

第 1 节原则 15 的落地：角色、名字清理这类判断不再是工具内置，而是 AI 在看过样本后写出的**规则型意图**（选择器是名字正则或材质，而不是具体对象）：

```
{ "selection": { "rule": { "name": "Blocker|Collision|^Block[A-Z]" } },
  "text": "这些是隐形挡墙",
  "formal": { "decisions": ["over @rule ~role=collision"] } }
```

工具按规则确定地执行；换一个美术团队，换的是意图，不是代码。原型的 `roles.json` 就是这种意图的雏形。

### 4.6 不做

- 不做自然语言的本地解析：翻译一律由 AI 做，工具只存、只绑、只执行形式化的部分。
- 不做意图之间的自动合并：后写的覆盖先写的，冲突由 checks 暴露。
- 不做多用户：意图有 author 字段，但没有权限与并发。

## 5. 逆向的新骨架

```
读取部件（GLB 节点、享元、连通分量、意图里的决定）
   │
事实（几何内核）：包围盒、主轴、薄度、平面聚类、连通性、接触对、同网格实例、同形候选
   │
检测器流水线（每个独立、可关、输出候选写法 + 它的描述长度下界）：
   基本体 / 板件 / 外壳-空腔-开口 / 并 / 扫掠 / 旋转体 / 台阶 / 平板 / 凸包 / 小场景（递归）
   阵列（平移、旋转、曲线、带例外）/ 镜像 / 类型（享元 → 几何同形）
   │
候选筛选：先按事实与长度下界剪枝（原型的“便宜的排除”系统化），再评局部分数；预算按候选数计
   │
关系：编译坐标版 → 事实 → 每物体一条主关系；可编辑性项让关系在长度相近时胜出
   │
校验 → 发射（全命名、带 ~src ~fit ~intent）→ 分块合并（跨块规律在合并后再找一遍）
```

与原型的差别：候选不是“全生成再比分”，而是事实先缩小集合；每个检测器有自己的测试语料与召回指标；语义判断（角色）从流水线里消失，变成读意图。

## 6. 评分修订

`S = L_stmt + L_mesh + R_src + R_recon + R_vol + E_edit`

- 前五项沿用原型的定义（铰链、同材质优先、网格按真实信息量、体积误差）。
- `E_edit`：坐标依赖的代价。每个用世界坐标定位的物体付一个小的固定项（量级相当于一个名字），让关系在描述长度相近时胜出；权重可配置，校准时报告它对真值指标的影响。
- 硬规则改为**具名约束**：`constraints: { solidFill: {maxWrong: 0.3, minVolume: 8}, keepLargeParts: {minSize: 1.0} }`，每条可关，报告里列出哪些候选因为哪条约束被否。
- 校准集：三个实战工程 + 至少两个外部 CC0 模型 + 一张不同团队的地图；校准序（全网格 > 全坐标 > 逆向 > 原文）与真值指标的单调性都要在外部数据上成立。
- 增量评分从第一天设计进去（原型是后加的），状态跨进程持久化。

## 7. 渲染

- **wgpu + WGSL**，一份着色器：浏览器 WebGPU（界面）、原生无头（agent 的 `render` / `compare`）。
- **基本体直绘**：光栅化每个物体的包围盒，片元里按种类做解析求交（盒、柱、锥、球、楔、凸包）或距离场步进（旋转体、平板）；`subtract / union / intersect` 在片元里组合，不做网格 CSG。扫掠与网格引用保留三角化路径作为例外。
- GPU 侧 BVH 或分块，目标是 3 万物体 60 帧；标注、聚焦、误差热力、角色显隐用实例属性。
- `compare` 的模糊与差分做成计算着色器。
- **只做 WebGPU，不做 WebGL2 后备**（用户决定，2026-10-12）：使用者是桌面 Chrome 上的开发团队，覆盖面不是问题；wgpu 的原生后端与浏览器共用同一份 WGSL。

## 9. 里程碑

| 阶段 | 内容 | 验收 |
|---|---|---|
| M0 规范 | `spec/` 全部章节；兼容性差异清单；corpus 搬入 | 规范能解释 examples 里每一条语句的含义 |
| M1 内核 + 编译器 | `s3d-geom`、`s3d-lang`（native + wasm）、事实、语义；CLI `compile` | examples 全部编译；事实与原型一致（按定义，不按字节）；wasm 在浏览器里跑同一套测试 |
| M2 评分 + 渲染 | `s3d-score`（含 E_edit、具名约束、增量）、`s3d-render`（无头 PNG、WebGPU 预览） | 校准序在 corpus + 外部数据上成立；SpaceCenter 预览 60 帧 |
| M3 逆向 | 检测器流水线、阵列 / 镜像 / 类型、关系、分块 | spaceport L0/L1/L2 真值指标不低于原型；三个实战工程的 compare 不差于原型 |
| M4 工程与协作 | 工程、层、**意图**（第 4 节全部）、提议、命令表（CLI / MCP / HTTP）、界面 | 一条意图走完“选 → 说 → 翻译 → 接受 → 重跑仍生效 → checks 报告”的全流程；角色全部由规则型意图给出 |

## 11. 风险

- **规范写不完就想写代码**：M0 是硬门槛，没有规范不开 M1。
- **Rust 的迭代速度**：逆向的启发式迭代会比 JS 慢；用检测器隔离 + corpus 指标自动化来抵消。
- **渲染路线是新的**：基本体直绘 + GPU BVH 不是现成库；M2 先做无头版验证正确性，预览性能不达标时降级为“直绘 + 实例化三角网格混合”。
- **意图的翻译质量**：AI 翻译错了会以提议出现，人要看得懂预览；effect 与 checks 是防线。
- **外部数据**：需要下载 CC0 模型与第二张地图，每次单独确认。
