# SVG3D 计划 2：人与 AI 协作的逆向工作台

> 定位不变：用语言描述世界，把重复与关系抽象出来，把世界压缩下来；逆向得到的工程高度可编辑，人与多模态模型在同一个工程、同一套工具上协作迭代。本计划接续 docs/PLAN.md 的“进展记录”，处理主会话确认的 12 项差距。
>
> 起草时核实到的新事实（影响优先级）：
> - **差距 11 的原因**：`tools/reverse.mjs` 的 `primitiveOf`（第 311–317 行）把不直立的盒子规范成“局部 y = 最长边”，第 333–335 行把不竖直的圆柱写成 `axis=x`。倾斜 25° 的光伏板因此写成 `box panel size=2.8,5,0.1 rot=…`，斜塔立柱写成 `cyl col axis=x rot=(0,0,1,85)`，局部 y 不再是站立方向，编译器 `onTest`（`src/s3d.js:2176`，要求 A、B 竖直轴平行且 A 底贴 B 顶）永远不成立。rotation 的 on 真值 237 条只找回 28 条，就是这个原因；不是事实推导的问题。
> - **L2 没有诚实的兜底**：`splitComponents` 拆出的分量 `name` 为空，`primitiveOf` 第 289 行的 mesh 退路要求 `part.name`，厂房被硬写成 `box volume_1 size=58,22,26 ~fit=0`。

> - 阵列成员行只有 `~fit` 没有 `~src`（emit 第 563/588/624 行），所以“逆向对象 ↔ 源部件”的对应目前只对普通物体成立。
> - reverse 测试全套 10.4 s；rotation（321 部件）单次逆向约 7 s。

## 1. 原则

延续 PLAN.md 的 9 条（描述而非生成、可逆性的操作定义、关系优先坐标是残差、MDL、几何客观语义分层、语义层只读几何、非破坏分层、诚实近似、核心小靠组合），补充：

10. **人与 AI 共享同一个工程与同一套工具。** 不给 AI 单独的接口：GUI 里人能做的每件事（看、查、做、评）都有同名的命令行工具；AI 用的工具与 GUI 调的是同一个函数。工程就是目录里的文本文件，两边都能读。
11. **工具确定、可复现。** 相同输入得相同输出（采样已用 `rng(seed)`），一律 JSON 输出；每次工具调用可以记录并回放。没有隐藏状态：选中状态、相机、批注、提议都是工程目录里的文件。
12. **AI 的修改以“提议”形式出现。** 提议是对某一层的一段差异（追加语句，或撤销某条语句），人可接受或否决；接受后才进入修改层 / 决定层。AI 永远不直接改 `base.s3d`（它是逆向重新生成的）。
13. **分数是目标函数，也是进度条。** 自评分数不依赖真值，由描述长度加残差构成；AI 以降低分数为目标，人以“解释率”看进度；有真值时再用 eval.mjs 校验分数本身。
14. **不为特定场景特化。** 新机制对任意集合、类型、规律成立；语言不增加只为某类资产服务的词。本计划新增的语言面只有：曲面锚点（3.5）、地形取点（3.6）、`~src` 的列表取值。决定层、提议、批注都不是语言特性，而是工具约定。

## 2. 协作循环的架构

### 2.1 参与者与数据流

```
 源模型 source.glb ──reverse(+decisions)──▶ base.s3d（机器层，可重生成）
                                               │ import
 人 ──GUI/编辑器──▶ edits.s3d  decisions.s3d  semantics.s3d  style.s3d
                       ▲            ▲
                       │ accept     │ accept
 AI agent ──propose──▶ proposals/NNN.s3d ◀── 人 reject/accept（GUI 或 CLI）
    │  ▲
    │  └── 读：outline / inspect / similar / slice / render(PNG) / score / inbox
    └───── 写：只写 proposals/ 与 state/agent.json
 GUI ──写──▶ state/selection.json（选中路径 + 相机）、inbox.jsonl（人的批注）
 score.mjs ──▶ score.json（总分 + 逐物体）──▶ GUI 热力图 / 进度条；AI 的目标函数
```

- **选中状态**：GUI 每次选中都写 `state/selection.json`（`{paths, camera:{pos,target}}`）。AI 的 `inspect --selection`、`render --focus=selection` 读它。这是人把“我说的是这个东西”交给 AI 的最简单通道。
- **批注**：人在 GUI 的“交给 AI”框里写一句话，连同当前选中写入 `inbox.jsonl`（`{t, paths, text}`）；AI 用 `inbox` 读（不自动轮询，人告诉它“看收件箱”即可）。
- **提议**：AI 写 `proposals/NNN-标题.s3d`，首行注释写目标层与理由（`// layer=edits  why=…`），正文是追加到该层的语句（撤销用 `// retract 路径 或 行号`）。工具 `preview NNN` 把提议叠加编译并算分数差；`accept NNN` 追加到目标层并把提议移到 `proposals/accepted/`；`reject NNN --why=…` 记到 `inbox.jsonl`，AI 下次能读到否决理由。
- **分数**：`score` 写 `score.json`，GUI 顶栏显示解释率与总分，对象列表可按“逐物体代价”排序并热力着色。

### 2.2 工程目录布局

```
myworld/
  project.json         源模型路径与哈希、层顺序、容差与分数常数、单位
  source/world.glb     源模型（只读，或 project.json 里写外部路径）
  parts.glb            逆向拆出的部件（L2 分量等源文件里没有节点的部件），mesh 引用的目标
  scene.s3d            组合根：按顺序 import 下面各层（GUI 与工具只编译它）
  base.s3d             逆向基础层（机器生成；带 ~fit ~err ~src）
  base.map.json        逆向对象路径 → 源部件列表、拟合候选、被决定层锁定的项
  decisions.s3d        决定层：人 / AI 对逆向的约束（4.6），reverse 的输入，不进 scene
  edits.s3d            修改层：几何修改（over / drop / copy / 新物体 / def 扩展）
  semantics.s3d        场景语义：concept / pattern / check（import lib/semantics.s3d）

```

| 文件 | reverse | 人 | AI |
|---|---|---|---|
| base.s3d / base.map.json / parts.glb | 写 | 不写 | 不写 |
| decisions.s3d | 读 | 写 | 经提议 |
| edits / semantics / style | — | 写 | 经提议 |
| proposals/ | — | accept / reject | 写 |
| state/、inbox | — | GUI 写 | 读；agent.json 自己写 |

## 3. 自评分数（`tools/score.mjs`）

目标：没有真值也能算；AI 的目标函数；人的进度条；逐物体可归因；防作弊。

### 3.1 定义

`S = L_stmt + L_mesh + R_src + R_recon`，越低越好。

**描述长度 `L_stmt`**：对 `base.s3d` 与 `edits.s3d`（不含 decisions、semantics、style、注释、`~meta`）的语句文本计价：
- 关键字、名字、属性键、引用、方向词：各 1。
- 数字：`1 + 0.5 × max(0, d − 1)`，d 为去掉末尾零后的小数位数。`26`→1，`31.5`→1.5，`38.2711`→2.5，`0.644711`→3.5。于是 `at=38.2711,1.6453,42.7711` 计 8.5，`on=pad` 计 2，`on=terrain[0.25,1,0]` 计 4.5。
- `def` 体只计一次，实例每个按自己的语句计；`repeat`、`mirror`、`rotate` 按写出的文本计（这正是压缩得分的来源）。
- `mesh` 语句照常计 token，另加 **`L_mesh = c_mesh × log2(1 + T)`**，T 为被引用网格的三角形数（“仍以原始网格保留的部分”按数据量计）。

**残差**（按几何，双向，Chamfer 式）：
- 源侧：对每个源部件表面采样（复用 `samplePoints`，600 点，固定种子），求到重建几何表面的距离 `d_i`（重建几何用 `src/geometry.js` 的 `itemGeometry` 生成，three-mesh-bvh 做最近点查询，两者都已是依赖；mesh 引用按源网格本身，距离为位姿误差）。`r_i = log2(1 + d_i/δ)`，`d_i` 以 `D_max` 封顶（默认 2 m，覆盖缺失即重罚）。**`R_src = c_res × Σ_部件 log2(1 + T_o) × mean_i r_i`**：部件越复杂，错误解释越贵。
- 重建侧：对每个重建物体表面采样，求到源表面的距离，同样公式，按物体归因，`R_recon`。它惩罚凭空多出的物体。

默认常数（写进 project.json，可调）：`δ = 5 mm`，`c_res = 4`，`c_mesh = 10`，`D_max = 2 m`。由此得到的拐点：mesh 引用的代价相当于平均误差约 4.7δ ≈ 2.3 cm 的拟合——误差大于此的拟合不如诚实地保留网格，小于此的拟合赢。

**汇总输出** `score.json`：`{S, L_stmt, L_mesh, R_src, R_recon, S_mesh, explain: 1 − S/S_mesh, objects:[{path, src, stmt, mesh, r_src, r_recon, meanErr, maxErr, tris}], worst:[…前 20]}`。`S_mesh` 是“全部写成 mesh 引用、用世界坐标定位”的基线分数，`explain`（解释率）是进度条；`worst` 是“下一步该修什么”的清单。

### 3.2 防作弊

| 作弊 | 为什么失败 |
|---|---|
| 全写成 mesh 引用 | `L_mesh` 按三角形数计，一个 500 三角形的部件约 90，而一个合格的 box 约 8 |
| 写成大量高精度坐标 | 数字按小数位计价；坐标不减少残差（拟合已精确），所以只增不减 |
| 删掉难的物体 | 源侧采样点找不到表面，`d_i = D_max`，`r_i ≈ 8.6`，再乘复杂度 |
| 凭空添加物体“填”残差 | 重建侧采样归因到该物体，`R_recon` 上升 |
| 把误差藏进 `~err` 元数据 | 元数据不计长度，残差按几何重算，不读 `~err` |
| 用超大 δ | δ 是工程设置，评测与实验里固定；报告里必须打印 δ |

### 3.3 与 eval.mjs 的关系与校准验收

- eval.mjs 继续作为有真值时的基准（形状、事实 F1、压缩召回、语义 F1）；score.mjs 是无真值的目标函数。两者都读同一份编译输出（`compile().items/nodes`）。
- **校准验收**（M0 必须通过，常数可调但一旦定下写进 project.json 默认值）：对 spaceport 的 `{全 mesh 基线, 全 at= 基线（reverse 的 absSrc）, compress=false, 完整逆向 L0, 手写原文}` 五个版本，分数必须严格递减；对 L0/L1/L2 三档，分数与 eval 的 `statementRatio × (1 + coordinateRatio)` 同序；rotation 修复差距 11 前后分数应下降（关系取代坐标）。
- M0 的 AI 在环实验里有真值（L2 的真值就是 examples/spaceport.s3d），记录每次迭代的 S 与 eval 指标，报告相关性。

## 4. 模块设计

### 4.1 离屏渲染（`tools/raster.mjs`，零新依赖）

- 输入：`compile()` 结果（或源 GLB 的部件三角形），输出 PNG（用 `node:zlib` 自写 PNG 编码器，约 40 行）与同名 JSON 图例。
- 纯 JS 光栅化：`itemGeometry` 得到世界坐标三角形 → 透视 / 正交投影 → 扫描线 + z-buffer，平头着色（法线·光向 + 环境），再输出三种缓冲：**颜色图**、**ID 图**（每个对象一种唯一色，图例 `color → path`）、**深度图**。
- 模式：`color`、`id`、`diff`（源与重建同相机，逐像素深度差热力图）、`error`（按 `score.json` 的逐物体 `meanErr` 着色）、`labels`（ID 图上用 5×7 点阵数字标注对象编号，图例给路径；不渲染文字字形，数字足够）。
- 相机预设：`iso`（0.75,0.55,0.9 方向，与 `Viewer.frame` 一致）、`iso2`、`top`、`front`、`left`，以及 `--focus=路径|selection`（按 `nodes[].box` 取景，取景逻辑与 `render.js` 的 `frame(box)` 相同，保证人看到的与 AI 看到的是同一视角）。默认 1024²，`--size` 可改。
- 性能目标：1e5 三角形 × 6 视角 < 5 s。
- 备选（不推荐）：Puppeteer 截图（新依赖、慢）；Node 里跑 WebGL（headless-gl，编译原生模块）。保留“浏览器预览里按同一相机预设截图”作为对照：在 `Viewer` 加 `snapshot(preset)`，用现有 `preserveDrawingBuffer`。

### 4.3 类型抽取（def）

两条线索，先精确后近似：

1. **享元线索（引擎层）**：`partsOfDocument` 改为记录 `{meshId（Map 按 gltf Mesh 对象分配）, nodeMatrix, localTris}`，世界三角形按需生成。同一 `meshId` 的节点就是同一类型的实例；拟合只在网格局部坐标做一次（也是性能收益），实例位姿 = 节点矩阵。若一个 mesh 有多个 primitive（多材质），实例是一个 `group`。
2. **几何同形组**：对不在阵列里的部件，按接触图（`compile().facts` 的 on/against/touching）取连通分量作为“候选单元”；单元指纹 = 成员签名（kind + 量化尺寸 + 材质）与成员间相对位姿（量化）的规范排序。指纹相同的单元 → 一个 `def`，每个单元一条实例语句。规范化借用 `detectArrays` 的 `sameOrientation / relPose / samePose`。
3. **发射**：`def 名(…) { 成员，内部用 on/against/at=兄弟锚点 }`，实例 `名 inst_k on=… turn=…`（实例的定位走现有 `chooseFor`）。名字：有 glTF 名取公共前缀（`memberNames`），否则按语义库概念（`semanticNames` 扩到 def）。
4. **实体化**：阵列 / 镜像检测改为对“实体”（普通物体、def 实例、已识别阵列）进行，这样“一排房子”写成 `repeat { house h }`、“对称的两座塔”写成 `mirror`。顺序：享元类型 → 几何类型 → 阵列（对实体）→ 镜像（对实体）。
5. **接受准则**：按 3.1 的长度计算，`def` 体一次 + 每实例一条 < 原来逐个写出，才采用（`worth()` 的推广）。只有尺寸不同 → 参数化（M5）；少数部件增删 → `def B : A`（M5）。
6. 验收：spaceport_edit 的 `hangar2`（copy 出的第二座厂房）在 L1 逆向里写成 `def shed` + 两个实例；三栋随意摆放的同款房子（新示例 `examples/village.s3d`）L1 写成 def + 3 实例；ABeautifulGame（见 M2）32 个棋子写成 6 个 def。

### 4.4 容差与近似规律

- 一个来源：`project.json` 的 `tolerance = {abs: 0.01, rel: 0.005}`，`τ(实体) = max(abs, rel × 实体尺寸)`。现在散落的常数（`detectArrays` 的 `tol = 0.004 + 1e-4·scale`、`detectMirrors.matches` 的 0.004、`fitAlong` 的 5e-4、`sameSize` 的 0.01+0.005v、校验的 2e-3 / 0.025、`TOL = 0.02`）全部改为由 τ 派生；决定层可以逐实体覆盖（`~tol=`）。
- 阵列步长、旋转角、曲线控制点改为对全部成员做最小二乘（现在取自第一对），记录最大偏差写进 `~err`。
- 接受准则改为 MDL：`cost(规律语句) + 残差(err) < cost(逐个写出)`，残差按 3.1 公式；校验步比较中心时用 τ 而非 2e-3。
- **数字最短化**：发射前对每个数字做“最粗精度搜索”——逐位减少小数位，只要校验（中心误差 < τ）仍通过就采用。这是通用的描述长度优化，对真实模型的浮点噪声（0.6999999）特别有效。
- 新导出档 `--level=L3`（`tools/export.mjs`）：L2 之上再加顶点抖动 σ=0.3 mm、部件位姿抖动 2 mm、随机 3% 部件重复（模拟 LOD）、随机顺序。在拿到真实模型之前，用它验证容差机制。验收：spaceport L3 的阵列召回 ≥ 90%、分数低于 L3 的“全 at=”基线。

### 4.5 规模

- **空间索引**：`tools/spatial.mjs`，均匀格网哈希（格长 = 中位实体尺寸 × 4），接口 `near(p, r)`, `inRegion(box)`，供 `slice`、阵列候选、镜像候选、校验用。
- **阵列检测**：候选运动只从每个实体在同签名组内的 k 近邻（k=8）生成（阵列由相邻成员产生），链的延伸用“量化中心 → 实体”哈希查表，整体 O(n·k)。镜像：按签名桶分组，候选平面用 `(n, d)` 量化哈希聚合，替换现在线性 `planes.find`；每桶上限 2000，超出按区域分块。
- **校验**：emit→compile→verify 最多 6 轮全量编译；改为只对本轮改动涉及的单元在其区域内局部编译（区域 = 单元包围盒 + 参照物），全量编译只在最后做一次。
- **分块**：`reverse --region` 产出 `base/tile_i_j.s3d`，`base.s3d` 只 import 它们；跨块的阵列 / 镜像在第二遍“合并块边界”里处理（只看每块边缘 1 格的实体）。
- 压力场景：`examples/stress.s3d` 由脚本把 spaceport 复制成 10×10（约 1.1 万部件）与 32×32（约 11 万）网格，带随机 yaw。验收：1e4 部件逆向 < 60 s、1e5 < 15 min（M3）；编译 1e5 节点 < 20 s。

### 4.6 纠偏持久化：决定层 `decisions.s3d`

决定用语言本身写，reverse 把它当作必须满足的约束读入，而不是另造 JSON：

```
// 这些源部件是同一个物体，叫 hangar，保留为网格
mesh hangar ~src=["merged_1#1","merged_1#7"] ~lock=shape
// 这些是一个阵列（人看出来的，检测器没认出来）
repeat lamps n=6 ~src=["part_0012","part_0030",…]
// 这三栋是同一类型
def house ~src=["part_0101","part_0102","part_0103"]
// 这个部件是噪声 / 碎片，忽略
drop ~src="merged_4#188"
// 这个物体的定位关系不要再改（人改过了）
over bunker ~lock=place
```

- 语义：`~src` 绑定源部件；`~lock=shape|place|all` 表示保持上一次 base 里该对象的形状 / 定位 / 全部；`def`/`repeat`/`mirror` 带 `~src` 表示“这些部件构成该构造”，reverse 先满足这些，再对剩余部件跑检测。满足不了（例如所标部件根本不等距）时写进报告 `unsatisfied`，并在 base 里保留为逐个写出 + `~decision=失败原因`。
- 决定层不进 scene（它不描述几何，只约束逆向），所以不计入描述长度；它的效果会体现在 base 里。
- 源模型改版时：`project.json` 记源哈希；部件引用先按名字，再按 IoU 重绑（`semanticNames` 的 previous 匹配逻辑），绑不上的决定列为 `dangling`。
- 稳定命名继续按现有机制（上一次 base 作为 previous）；`check` 命令报告修改层里失效的路径。
- 验收：对 spaceport L2 人工写 5 条决定（厂房分组、路面保留网格、楼梯视为台阶…），重跑 reverse 后 5 条全部生效且修改层路径 100% 命中；换成 spaceport_edit 的 L2 重跑，决定重绑成功率 ≥ 80%。

### 4.7 图形界面的协作功能（`index.html` / `src/app.js` / `src/render.js`）

- **本地服务** `bin/serve.mjs`（node:http，零依赖）取代 `python3 -m http.server`：静态文件 + `/api/project`、`/api/file/<name>`（GET/PUT）、`/api/run`（调用 2.2 的命令，返回 JSON）、`/api/render`（PNG）、`/api/proposals`、`/api/inbox`、`/api/selection`。GUI 和 CLI 调同一批函数。无服务（静态托管）时 GUI 退化为现在的单文件预览。
- **工程视图**：打开目录（`?project=`），文件标签 base（只读、灰色）/ edits / decisions / semantics / style；编译的是 scene.s3d（`preload` 已支持 import）。
- **选中面板**（替换现在只定位源码）：选中后显示 `inspect` 的内容——所属阵列 / 镜像 / 类型（点一下高亮全部同类：`kind(T)` 或同阵列成员）、关系列表（点一条高亮两者，复用 facts 面板逻辑）、来源部件、逐物体分数。多选 shift。`Viewer.highlight` 已支持多路径。
- **对比与误差**：视图模式切换 实体 / 源模型叠加（加载 source.glb 为半透明，复用 `addMeshRef` 的加载器）/ 误差热力（按 score.json 给材质着色）。
- **交给 AI**：输入框 + 当前选中 → `inbox.jsonl`。**提议面板**：列出 proposals/，点一条即叠加编译预览（高亮改动的对象、显示分数差与编译错误），接受 / 否决（带理由）。
- **顶栏进度条**：解释率、总分、最差 5 个对象（点击定位）。
- **多视角一致**：`Viewer.snapshot(preset)` 使用与 raster.mjs 相同的相机预设，人与 AI 讨论“iso 视角左上角那个”时指的是同一张图。

### 4.8 浏览器内逆向

- `partsOfDocument(doc)` 已不依赖 Node；把 `readParts` 的 `NodeIO` 留在 `bin/`，浏览器用 `@gltf-transform/core` 的 `WebIO`（同一包，import map 加一项）读 GLB，然后在 Web Worker 里跑 `reverse()`（纯 JS）。写回 base.s3d 走 `/api/file`；无服务时下载文件。
- `raster.mjs` 与 `score.mjs` 同样是纯 JS（three 在浏览器可用），也可在 Worker 里跑，GUI 的热力图不必依赖服务。
- 验收：在浏览器里拖入 spaceport.L1.glb → 逆向 → 结果与 CLI 逐字节一致（确定性）。

### 4.9 几何词汇补全与 L2

按收益排序：

1. **差距 11 修复（M1 之前，小改）**：`primitiveOf` 的规范化改为“局部 y 取最接近世界上方向（或支撑物上方向）的轴，x 取其余中较长者”；不竖直但 `d[1] > 0.7` 的圆柱写成 `axis=y` + `rot=`，只有接近水平的才 `axis=x`。随之调整 `sameOrientation` 的 `symY` 分支（比较整条轴而不是只比 y 分量）与 `detectArrays` 环检测取轴的方式。验收：rotation on/against 召回从 0.126 升到 ≥ 0.9，坐标依赖率 34% 降到 < 10%。
2. **L2 的 mesh 兜底**：拆出的分量写入 `parts.glb`（用 `@gltf-transform/core` 的 Document 建节点），`primitiveOf` 去掉 `part.name` 条件，mesh 引用指向 `parts.glb#merged_1_1`。验收：L2 不再出现 `~fit=0` 的基本体；L2 分数显著下降。
3. **steps**：`detectArrays` 认出的线性阵列若步长 ≈ (踏步宽, 踏步高, 0) 且成员是同尺寸盒子，发射为 `span … steps=n`（原文的 16 级楼梯在 L2 里是 16 个盒子，这是 L2 “172 对 111”的主要来源之一）。
4. **revolve**：轴对称检测（法线聚类得轴，点到轴距离按高度分箱得轮廓，Douglas–Peucker 简化到误差 < τ），发射 `revolve profile=[…]`；火箭整流罩、雷达天线不再退回 mesh。
5. **曲面锚点（3.5）**与**地形取点（3.6）**：语言侧按 PLAN.md 原设计；逆向侧 `chooseFor` 在 `on` 的参照物是 mesh 且满足高度场条件时写 `on=terrain[u,1,w]`（表面取点），罐体侧面的接管写 `against=tank.side[θ,v]`。地形判定：mesh 的 xz 投影面积 ≫ 厚度且竖直射线单值。
6. **sweep / pipe**：管状检测（截面恒定、骨架曲线）放到最后，先依赖 mesh 兜底 + 分数识别“最值得修的部件”。
7. **L2 过碎**：拆分后把“共面贴合且材质相同”的分量先尝试合并拟合（合并后误差更小则合并），其余交给决定层由人分组。

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 分数常数不当，AI 学会钻空子 | 3.2 的作弊表作为 score 的单元测试；E1 有真值，发现 S 下降而 eval 下降即调常数并记录 |
| 真实模型的几何不是基本体能表达的（异形件、地形、合并网格） | mesh 兜底 + 决定层 + 分数指出最值得修的部件；目标是“压缩能压缩的，诚实保留其余”，而非 100% 拟合 |
| 享元线索缺失（烘焙过的地图） | 几何同形组兜底；L1/L2 已无名字，现有指标就是这种情况的下限 |
| O(n²) 在真实地图上不可用 | M3 的索引；在 M2 之前先用 stress 示例测量，防止真实模型卡死 |
| 决定层与自动检测冲突（人说是阵列，几何不等距） | 决定优先 + 容差放宽到决定给出的 `~tol`；满足不了写 `unsatisfied` 报告，不悄悄忽略 |
| 工程多文件后路径失效 | 稳定命名 + `check` 报失效路径 + 决定层 `~lock` |
| GUI 与 CLI 行为分叉 | 同一函数表生成 CLI、MCP、HTTP 三个入口；E2 用 GUI 跑的每一步在日志里都有等价 CLI 命令 |
| 外部模型下载与版权 | 只用 CC0 / CC-BY 的样例，每次下载请用户批准；用户自己的地图不入库、不提交 |
| 软件光栅化画质一般 | 多模态模型要的是形状与标注而非真实感；需要时 GUI 用 WebGL 截同视角对照图 |

## 9. 明确不做的事

- 通用约束求解器、物理、碰撞避让：仍是“每个物体一条主关系 + 相对锚点”；真实模型里相交 / 嵌入的物体用 `at=B[u,v,w]` 表达，已够用。
- 纹理、UV、法线贴图、动画、骨骼的还原：语言只管外包络与关系；材质只到基础色 / 金属 / 粗糙。
- 基于学习的 L2 分割或 Python 工具链：先靠 mesh 兜底、分数指引与人的决定层；PLAN.md 里“允许 Python 预处理器”的决定推迟到 M5 之后再议。
- 多用户实时协作、账号、云端：工程是本地目录，协作是人与 AI。
- 把提议做成通用 diff/merge 系统：提议只追加语句或撤销语句，依靠“后写覆盖先写”；折叠冗余 `over` 的 `compact` 工具不做。
- 为某类资产（房屋、树、车）写专用识别器：一切通过几何 + 语义库概念 + 人定义的 concept。
- 为了 AI 阅读而改语言语法（例如 JSON 化）：AI 读 outline / inspect 的 JSON，写的仍是 SVG3D。

## 审阅意见（主会话）

### 第二步：按目标细化（refine）

- **拆分**：细化 = 在物体自己的坐标系里，对它的源网格做一次小型逆向。网格由多块组成（一层层阳台板、两柱一梁）时按连通分量拆开，再走完整的逆向流程（逐块拟合、关系、阵列、镜像）；只有一块、基本体又拟合得不好时，用“体素占据 + 贪心合并成盒子”。
- **写回、保住骨架**：类型实例 → 同名扩展 `def T : T { drop body; group body envelope=… { … } }`（所有实例一起变细）；普通物体 → 保名换形 `over x : group envelope=… { … }`。新增语言属性 `envelope`（组的名义外包络）：关系、锚点、定位点都按它算，与内容无关，于是拆成多少块，挂在它上面的物体都不动（宿舍区一栋楼上挂着 50 多个物体；不保包络时细化让它们整体漂移，分数 +9175）。空间事实、渲染、评分仍按真实内容。
- **评分随精度**：细化的预览与自动模式按目标档位的 δ 评分；残差权重改为 log2(1 + 面积/δ²)（这块表面在当前精度下有多少个 δ 见方的格子）——精度要求越细、表面越大，同样的误差越贵；重建侧的权重以顶层语句为单位、内部按面积分摊，拆分本身不受罚。校准顺序在 spaceport、rotation 上仍成立。
- **顺带修的 bug**：GLB 节点名不唯一（同一分区同一网格的多个实例同名），`~src` 只记名字时细化与网格引用都会拿到别的实例——来源标识改为唯一（重名的写成 `名字@k`，预览器同样解析）；修正后宿舍区的基线分数 51609 → 49495。阵列成员没有 `~src`：借同类型的其他实例，或按包围盒重叠度找源部件。
- **命令**：`refine <路径…> | --worst=N [--to=structure|detail] [--apply]`；`refine --auto --budget=N --target=解释率`。
- **效果**：宿舍区 `Dormitory_01C`（5 个实例的类型，由 52 块阳台板组成）拆成 52 块、4 组阵列，平均误差 0.9 → 0.09，按结构档评分 −960；外墙组合 `ExterWall_01F` −20。

### A1 场景单位（2026-10-10）

- **约定**：`project.json` 加 `unit`（每个场景单位多少米，默认 1）。对外的长度一律按米——档位的 τ、分数的 δ 与 `dMax`、`score` 输出的 `meanErr` / `maxErr`；进入几何计算前换算成场景单位。分数换算后与单位无关（残差是 d/δ，面积权重是 面积/δ²）。
- **逆向**：`reverse(parts, { unit })` / `setFidelity(档位, unit)`：S 再除以 unit；数字位数按 10^−位数 米折算（`digitsFor`，stud 与米相同，厘米、毫米更少）；原来按米写死的绝对容差（镜像候选面、竖杆顶点、曲线复用、尺寸签名的厘米量化、方盒的宽深比较、远处成员的位置容差）乘 M = 1/unit。顺带修了阵列聚类容差里相对项被换算两次的问题（米制下不受影响）。
- **编译器**：空间事实的容差 `FACT_EPS`（2 cm）可以由 `compile(…, { factEps })` 传入；工程、逆向、细化都传 `FACT_EPS / unit`。界面直接打开 `.s3d` 时仍是默认值。
- **工具**：`init --unit=`（不给时按部件尺寸的中位数猜：> 50 猜厘米，> 500 猜毫米，否则米；猜不出 stud 这类非公制单位，所以结果里总有 `unitNote` 提示确认），`reverse --unit=` 改单位，`bin/reverse.mjs --unit=`。细化的体素大小、小数位、局部分数都按单位换算。
- **验证**：spaceport L0 按米、stud、厘米各逆向一次（结构档、语义档），形状、阵列、镜像完全一致，残差差别 < 1%（写进测试）；描述长度因数字的写法不同而不同（3 m 在 stud 里是 10.7）。`unit = 1` 时原有 78 个测试结果不变，spaceport / E1 的分数不需要重新校准。
- **H1 上的效果**（语义档重新 init）：按米（错误的假设）S = 71318，解释率 0.575，最差物体的平均误差 1.6 个单位、贴着 `dMax`；按 stud S = 49195，解释率 0.707，误差约 1.4 m、离上限 2 m 还有余量。结构档自动细化（预算 4）接受 3 个，−455。
- **已有工程**：`project.json` 没有 `unit` 的旧工程按 1 处理（与以前一样）；要换成 stud 用 `reverse --unit=0.28 --fresh`，之前在米制尺子下做的细化需要重新跑。（当时的 `work/*/auto` 与对照工程已删除，现在用 `work/h1/final`、`work/dorm/final`。）

### A4 增量评分（2026-10-10）

- **时间花在哪**：H1（1964 个源部件、2006 个重建物体）一次评分 12 s，编译只占 0.3 s；`R_src`（约 142 万个源采样点）与 `R_recon`（约 120 万个重建采样点）的最近点查询各约 6 s。
- **做法**（`score({ …, cache })`，`scoreCache()`）：
  - 源侧固定的东西（三角形数组、按颜色分组的 BVH、面积、包围盒、基线 `S_mesh`）只算一次；
  - `R_recon`：源固定，每个重建物体的残差只取决于它自己，按“路径 + 颜色 + 几何哈希”缓存；
  - `R_src`：每个源部件逐点记下距离与最近的物体。和上一次评分比，只重算两种点：最近的物体被删掉了的点；离某个新增物体比现在的距离还近的点——先用包围盒初筛，再用新增物体单独建的 BVH 按真实几何判断（同材质规则、多计的 δ 与正式查询一样）。某种颜色的物体整组出现或消失时，这种颜色的源部件全部重算；改动的物体超过三成时直接全部重算（挂靠关系让大半个场景都动了，逐点核对不比全算省）；
  - 逐点按原来的顺序累加，增量与全量的分数逐位一致。只有“并列”的点（到两个重合的物体距离相同，如贴在隔墙上的百叶窗、摆在同一位置的两个柜子）归属可能不同——这取决于 BVH 的结构，全量评分本身也会因为别处的改动而变，测试里不要求它一致；
  - 缓存挂在工程上（`project.mjs` 按目录保存源部件与评分缓存，源模型文件变了就重读），常数不同（细化时用目标档位的 δ）各自一份状态；`S3D_TIMING=1` 打出各阶段耗时与重算了多少部件、多少点。
- **效果**：
  - H1（stud）语义档 → 结构档自动细化，预算 4：结果与之前完全相同（同样的选择、同样的分数变化，89168.09 → 88712.62），70 s → 25 s；第一次全量 12 s，之后每次增量 0.3–1.5 s（类型细化动了 2 个实例、24 块：检查 1324 个部件，只重算 10314 个点）。剩下的时间主要是生成细化候选。
  - 宿舍区（stud，新建）预算 10：43 s（以前估计 5 分钟），接受 8 / 10，92583 → 87654（−4929）；`Dormitory_01` 类型这次覆盖到了（17/35 块，−2068）。增量评分每次 0.17–0.48 s。
- **没做的**：缓存只在一个进程里有效，命令行每次调用仍是全量（12 s）；可以把逐点结果存到 `state/` 里跨进程复用。描述长度没有做增量（全场 0.1 s，不是瓶颈）。

### A3 邻域评分（2026-10-10）

- **原因**：以前的局部分数只和这个物体自己的源网格比、不分材质、采样也与全场不同。全场评分里还有三样它没看到：附近的源部件（候选几何可能去解释、或者挡住邻居）；同材质规则（量到同材质的表面，没有时多计一个 δ）；**材质继承**——体素候选没写材质，单独编译时是默认灰色，写进场景后继承原物体的 `mat`（往往正好与源部件同色）。宿舍区三角梅的体素候选因此局部算“变差 95”，全场却是“变好 64”。
- **做法**：`neighborhoodScorer`（score.mjs，取代 `localScore`）：源侧 = 这个物体的源部件 + 离它不超过 dMax 的其他源部件，采样方式与种子同全场；重建侧 = 候选几何 + 附近其他重建物体，同材质规则按全场的颜色集合判断；候选到源的残差同全场（种子取自写进场景之后的路径，一个顶层语句共享面积权重）。邻居源点到“其余物体”的距离只算一次，每个候选只算到候选几何的距离、取小。候选在物体坐标系里编译，评分前换回世界坐标；没写材质的部件按原物体的颜色计价。
- **效果**（结构档自动细化，预算 10，新建的 stud 工程）：两个区域 20 次尝试方向全部一致；普通物体的邻域评分与全场变化相差不到 0.1（−301.9 对 −301.86），类型按实例数近似，相差在 20% 以内。H1 接受 10 个，89168 → 87299（上次预算 4 接受 3 个，被全场否决的那面外墙这次在邻域评分阶段就跳过了）；宿舍区接受 10 个，92583 → 87278。
- **还可以做**：类型的邻域评分只看一个实例再乘实例数；可以对所有实例逐个算邻域（类型的实例数通常不多）。

### A5 逐层细化（2026-10-10）

- 细化时分量在**世界坐标**里拆（以前在物体坐标系里拆，顶点焊接的取整会随坐标系变），编号与 `splitComponents` 一致；嵌套逆向输出的子块保留 `~src="部件#分量"`，换成体素的子块组也带上。
- `refineProposal` 解析来源：先按完整名字找源部件（L2 的部件名本身带 #），找不到就按“部件#分量”取分量，可以嵌套（`部件#3#0`）；候选从这个分量生成，邻域评分的“自己”仍是整个源部件。`--auto` 不再跳过已细化物体内部带来源的子块（整体体素那样没有来源的仍跳过）。
- 局限：类型内部的子块（细化过的类型）的 `~src` 指向细化时借用的那个实例，换一个实例几何对不上，暂不支持再细化（明确报错跳过）；要支持需要把子块的细化写进 def 扩展。
- 效果：H1 预算 16，接受 16 个、16/16 方向一致，89168 → 86784；其中两个子块（外墙的 `box1`）被尝试过，邻域评分判断不值得再拆。

### B1 细化独立文件、按楼栋分区（2026-10-10）

- **细化独立文件**：`refine --auto` 接受的每一项写进 `edits/refine-<目标>.s3d`（重名加序号），`edits.s3d` 只追加一行 `import`；评分时修改层的 import 一并计入描述长度（`geometryFiles` 对基础层、修改层都展开 import）。撤销一项细化 = 删掉那行 import。
- **按楼栋聚组的分区**（`split.mjs`）：每个物体跟着支撑它的物体走（`on=` 立在上面、`against=` 靠着；锚点 `at=B[u,v,w]` 只是就近取的参照，不用）；没有支撑关系的，跟着水平投影包含它中心、占地至少是它两倍的最大物体（楼栋外壳、院墙、路面）。只往不比自己小的物体合并；覆盖全场景四分之一以上的物体不当组的根。连成的树是一组；先按位置打包整组，一组超过行数上限时组内再按位置拆。宿舍区：7 个分区文件，每个 1–40 组（只用支撑关系时几乎聚不起来：语义档逆向大多写锚点，`on=` 很少）。

### A2 板件分解（2026-10-10）

- **做法**（`tools/panels.mjs`）：三角形按所在平面聚类（法线 8° 以内、偏移在半个格子以内，接近坐标轴的方向吸附到轴上）；每个平面在板内二维坐标里栅格化（每格 2×2 个子采样点，盖住 2 个以上才算占用），贪心合并成矩形；方向相反、相距不超过 1 m 的两个平行面配成一块板，厚度取两面的距离，配不上的单面薄板按 max(2τ, 10 cm)。墙（法线水平）写成直立的盒子（`turn=`），楼板、坡道的盒子 y 轴沿偏上的法线。一块板的覆盖是“一个大矩形挖掉几个洞”、并且 `subtract { box body ; box hole … }` 更短时写成 subtract。块数超过上限就把格子放粗（×1.6）再来。不认具体的建筑，只用平面、方向与覆盖。
- **接入细化**：整体板件候选（三种格子：2τ / 4τ / 8τ，块数上限 120 / 60 / 30）；嵌套逆向里拟合差的大分量除了换体素，再多一种换板件的变体。邻域评分来挑。
- **效果**：合成的空心楼（0.3 m 外墙、门洞、一层楼板）：板件 13 块，源侧残差 0，总分 150.5，实心盒子 162.1（源侧残差 153.9）——写进测试。实战：H1 预算 16，楼梯类型选了板件（−348），合计 86784 → 86760；宿舍区连廊 `DormitoryPassage_01`（255 个分量，以前每个候选都不如现状）选了板件 28 块（−19）。H1 最大的那面外墙所有候选的残差只差一两百、描述要多上千，邻域评分判断不值得拆——它的误差主要不在这面墙自己身上。
- **没做**：按楼层水平切片求墙线（平面聚类已经覆盖了直墙；弧墙、斜墙会碎成很多小板）；把挂在同一面墙上的窗框、门框识别成阵列（板件之间的规律目前不压缩）。

### C2 台阶（2026-10-10）

- `fitSteps`（reverse.mjs）：基本体拟合得不好时（误差 > 0.05），用板件的平面聚类找朝上的水平面（踏面）：大小相近（面积在中位数的 50%–150%）、高度等差、水平中心沿一条直线等距排开（偏差 15% 以内）→ `span 名字 from=A to=B steps=n section=宽,厚`；踏面下面配得上朝下的面就用两者的距离当厚度，否则用一级的高度（实心楼梯，踏步连同踢面一块）。误差与其他形状同一套（采样点到踏步盒子的距离，按最薄方向归一化），比基本体好才用。台阶是绝对定位的（端点在父坐标系里），校验只比位置；镜像检测的签名用级数、截面、水平长度与高度，匹配时比较反射后的端点；类型体里的台阶把端点平移到类型坐标系（`at=` 对 span 不起作用）。
- 效果：basics 的楼梯 `span stairs from=-20,0,0 to=-14,3,0 steps=8 section=2,0.2`（原文 8 级、截面 2,0.2），包络误差 < 0.01；spaceport L0 的两段楼梯以前写成斜放的长盒子（拟合度 0），现在是 span + 镜像，形状正确率 1、镜像召回 1、语句数比 0.76；H1 的 `PaintingStairs` 类型（8 级）认出来了，实例位置与源部件对得上。
- **L2 的楼梯**（4.9.3 的另一半）：一串直立的薄盒子排成线性阵列，步长有水平和竖直两个分量、盒子沿水平步长方向的深度约等于水平步长 → 一段 span 代替这个阵列和它的成员（名字 stairs）。spaceport L2：语句数比 1.227 → 0.693，镜像召回 0.875 → 0.958（两段楼梯成了镜像）。校准测试相应调整：L2 的语句数现在比 L0 还少（楼梯压缩了、大块的合并网格写成一个实心盒子），只看语句数比已经不能给 L2 排序；改为“真值评测的形状正确率、阵列召回、镜像召回至少一项更差，分数更高”。
- **旋转体**（4.9.4）：`fitRevolve`：横截面接近圆形的坐标系里沿对称轴分 24 箱取最大半径得外轮廓（两端只看紧贴端面的点，尖顶的半径是 0），Douglas–Peucker 简化到最大半径的 1%，写成 `revolve profile=[(r,y); …]`（局部 y 是对称轴，原点在轴与 y=0 的交点）；误差是采样点到旋转面的径向距离，比基本体好、轮廓不超过 16 个点才用；网格面积不到旋转面面积的 60% 的不算（螺旋扶手曾被当成半径 9.48 的整个圆柱面）。语义档不用（灰盒一律用基本体）。spaceport 的整流罩：底部半径 2、高 7、尖顶 0.21（原文 `[(2,0); …; (0,7)]`）。阵列、镜像的尺寸签名改为用正则取全部数字（`profile=[…]` 这样的值以前会变成 NaN）。
- 没做：带内凹的旋转体（水池、碗：外轮廓法得到的是实心体，误差大而落选）；扫掠（sweep）；曲面锚点与地形取点。

### D1 第一遍板件（2026-10-10）

- **做法**（`tools/reverse.mjs` 的 `tryPanels`）：结构档里拟合差（拟合度 < 0.5 或覆盖率 < 0.3）、最长边 ≥ 2 m、至少 24 个三角形的部件，用细化的同一套 `panelLines`（格子 2τ / 4τ / 8τ，块数上限 120 / 60 / 30）拆成墙板、楼板、坡道，写成 `group 名字 { … }`。和现在的写法在这个部件自己的源表面上比评分（与全场同一套计价，`neighborhoodScorer` 只放这一个部件），板件更好才用。享元类型同样：类型体写成 `group body { … }`，残差按实例数计，现在的写法是基本体或“各实例引用网格”。语义档不试（一律用基本体当代理）；细化内部的嵌套逆向不试（它有自己的板件变体）。
- **几个便宜的排除**（板件很慢）：表面不到八成落在大平面上的（岩石、帘子）不试；现在的基本体残差已经很小的不试；每两个平面至少一块板、一块一行至少 6 个词，这个下界已经不比现在短的不试；板件候选的描述长度本身就不比现在短的不评残差；源部件的采样与 BVH 用到时才建。宿舍区 387 个候选里 44 个用了板件，逆向 6.2 s → 11.8 s；H1 5.7 s → 13 s。
- **容器按包围盒定位**：`group … at=` 与 `on=` 都把容器包围盒的底面中心放到那一点，不是原点。板件先编译一次取自己的包络，平移到“包络的底面中心在原点”；评分时的临时语句加 `pin=origin`。
- **关系按包围盒核对**：空间事实按真实几何（容器按里面的内容），`on=` / `against=` 却按包围盒放。宿舍楼 01B 的一块板搭在 01 的屋顶上，两者的包围盒却是重叠的——事实说 on，写出来就错了 95 个单位，校验退回坐标还连带挂在它上面的物体。`chooseFor` 现在只用包围盒也对得上的支撑 / 贴靠（A 的底面在 B 的顶面上、A 的那一面在 B 的那一面上，差不超过 max(0.0125·S, 取整步长)）。这一条单独对宿舍区没有分数变化（±0），H1 −127，校验不通过的次数宿舍区 61 → 34。

### 性能（2026-10-10）

目标：让 AI 每轮“改代码 → 跑测试 → 在实战工程上重跑”更快。约束：**输出逐字节不变**——每一步都与改动前的代码对比 dorm / H1 的语义档与结构档逆向（base/、base.s3d）和评分（score.json）、全部示例三个档位的逆向（57 个文件，含 parts.glb）、spaceport 与宿舍区的细化提议，都相同；浏览器内逆向（Worker）与 Node 里同一入口的结果哈希相同。

- **最近点查询**（`tools/nearest.mjs`）：评分的残差查询原来走 three-mesh-bvh 的 `closestPointToPoint`（每个节点、每个三角形都经过回调、Box3、Triangle 对象），占评分时间的七成。现在树仍由 MeshBVH 建，查询换成专用循环：直接读节点缓冲区，三角形顶点按树序排成连续数组。遍历顺序、剪枝条件、点到三角形的算法与 MeshBVH 逐步相同，所以距离逐位相同、距离相等时取到的也是同一个三角形（80 万次随机查询对拍无差异）。单线程快约 2.4 倍。
- **并行**：全量评分的 R_src / R_recon、邻域评分（细化挑候选）的查询按块交给 worker 线程（`closestMany`，SharedArrayBuffer 共享树与点）。`score()` 仍是同步的：主线程也领活干，干完用 Atomics 等其余的，结果写回各自位置，汇总顺序不变。点数少于 16384 时不分；浏览器里（没有 worker_threads）一律在当前线程算。
- **细化**：同一组分量的嵌套逆向原来按“原样 / 体素替换 / 板件替换”跑三遍，现在跑一遍、三种替换共用；体素化改成标量循环。
- **拟合与板件**：采样点的顶点去重先按精确数值去重、只对新值算 toFixed 键；meshVolume 用整数顶点编号代替字符串键；sdBox / sdTri2 / 圆台距离、uprightFrame、fitTube 的线段距离不再逐点建数组；planesOf 缓存每个方向簇的单位方向；栅格化去掉闭包。

### D2 基本体之并、外壳 − 空腔 − 开口（2026-10-10）

### D3 扫掠拟合（2026-10-11）

- **做法**（`tools/sweepfit.mjs`，`fitPart` 在基本体拟合差时试）：表面采样（不带顶点）→ k 近邻图（格网查找；边长不超过第 3 近邻距离中位数的 2.5 倍，免得宽的螺旋坡道跨到相邻的一圈；剪碎了从短到长补回，原图不连通时按分量间最短边连上）→ 从“离质心最远的点的最远点”按最短路给初始参数 → 主曲线迭代（分箱取质心、投影、重分箱 4 次；箱长先取截面周长 ≈ 表面积 / 长度，一箱转角超过 30° 就按比例加密，但箱长不短于四分之一截面周长——箱比截面细时折线会摆进宽度方向；不做平滑——三点平均每遍让弯处缩 (1 + cos β)/2）→ 两端按落在端段外的投影外推。
- **曲线**：只用中心线的内部点判断（端点是外推的），残差的均方根 ≤ 容差、最大 ≤ 3 倍才算对上；容差 = max(τ, 0.5 × 采样点到中心线的平均距离)。依次：水平圆弧（转过 20°–360°）、螺旋（竖直轴，高度随转角线性）、竖直面里的圆弧（平面取内部点水平坐标的主方向）、Catmull-Rom 样条（3–8 个控制点，相邻两段转角 ≤ 60°）。直的（偏离首尾连线在容差内，或不到连线长度的 5%）交给基本体。
- **截面**：沿拟合出的曲线按编译器的 `sweepFrames` 递推框架，量每个采样点的 (u, v)；按 1% / 99% 分位的中点把曲线重新定中两次（圆弧、螺旋改半径与高度，竖直圆弧平移平面，样条平移控制点），再取矩形（w、t 取 99% 分位）或圆（平均半径）里误差小的。
- **语义把关**（用户 2026-10-11：逆向追求语义与功能，像 AI 重建场景，不是点面重合）：拱高至少半个截面宽、长度至少 4 倍截面、侧面积与网格面积在 0.6–1.5 倍、截面误差 ≤ 0.15、享元类型的代表不试。第一版没有这些时，宿舍区冒出 220 多个“扫掠”（箱盖、护栏的立柱被串成来回折返的样条，长条花坛成了半径 36 m 的缓弧），全部是错的。
- **耗时**：先用 400 个点粗筛（中心线够长、不是直的），过了再用 1000 个点精算；同一网格（同缩放）失败过一次，其余实例不再试；采样种子由几何决定（三角形数与面积），重跑逆向结果不随部件序号变。基本体误差 > 0.15 才试；封闭网格还要求 V / A^1.5 < 0.04。宿舍区结构档逆向 15.8 s → 20.5 s（拟合 7.2 → 12 s），没有一个扫掠——这部分是白花的：真实场景里几百个拟合差的部件大多是家具。可以放进拟合 worker，但这里的部件几乎都是共用网格的（worker 只预先拟合不共用网格的部件）。
- **效果**（结构档）：curves L0 1684 → 1342（−20%）、L2 1853 → 1574（−15%），spaceport L0 1075 → 963（−10%）、L2 1329 → 1217（−8%）；宿舍区、H1 逐字不变。螺旋坡道（宽 5、3 圈）、扶手（圆截面 0.08）、拱、车道在 20 个随机种子下都稳定；spaceport 的路（原文是 4 点样条）有时写成圆弧、有时写成样条。
- **其它**：扫掠物体的曲线语句名 = 物体名 + `_path`，语义命名改物体名时一起改；“现在的写法”用于和板件等比较时把曲线语句一起带上（否则编译不了、被当成无穷贵，板件就“赢”了——宿舍区的花坛曾因此每个实例都成了一组板件）。
- **没做**：带内凹的旋转体（喷泉水池）仍不是扫掠（D5）；扫掠的阵列、镜像（每个都写在世界坐标里）；倾斜轴的螺旋、任意平面里的圆弧（落到样条）。

### D4 地形取点（2026-10-11）

- **语言**：曲面锚点 `B.top[u,w]`、`B.side[θ,v]`、`B.surface[θ,φ]`（README“锚点与度量”）。没有沿用 PLAN 原来写的 `on=terrain[u,1,w]`：那会悄悄改变已有工程里 `on=网格[u,1,w]` 的位置；`top[u,w]` 是新写法，盒子上与 `[u,1,w]` 相同。`against=` 的条件放宽为“锚点有法线”（包围盒的面或曲面锚点）。编译选项 `heightAt(src, x, z)`（源文件坐标里竖直射线碰到的最高点）提供网格数据；没有、或射线没碰到时退回包围盒的顶面，编译结果多了 `warnings`。
- **工具**：`tools/heights.mjs` 按源部件建 xz 格网取高度；工程的 `compile()` 在源部件读入后带上它；`runCommand` 在几何层里出现 `.top[` 时先读源部件（磁盘缓存）。逆向内部的编译、校验、语义命名同样带上。
- **逆向**（`chooseFor`）：按包围盒的 `on` 没有对上时，找俯视包含物体、占地至少四倍、像地形的网格（竖直范围不到占地短边的 30%，朝上的面投影起来是 0.5–1.3 倍占地——一层），取整后的 (u,w) 处表面高度与物体底面差不超过 max(0.0125·S, 取整步长) 就写 `on=网格.top[u,w]`。只用于顶层、直立的物体。
- **效果**：宿舍区 38 处（26 处立在同一块路面 RoadFacility_Ground_D_06 上，还有床上的枕头、沙地贴花上的东西），`on` 62 → 100、世界坐标 1551 → 1515；分数 47670 → 47950（+0.6%：`on=地面.top[0.123,-0.456]` 比 stud 一位小数的坐标长；支撑关系照规矩保留——它的价值是可编辑、语义对）。H1 14 处，61685 → 61727。spaceport 不变（地面是盒子）。不加地形判定时顶灯被写成“立在房间网格的顶面上”（射线碰到天花板），语义不对，所以要求一层。
- 测试：曲面锚点（有 / 没有网格数据、球顶、圆柱侧面 against、球面）；起伏地形上的箱子写成 `.top[u,w]` 且编译后落在表面上；两层楼板的网格不算地形，同样布置的单层起伏地面算。
- **没做**：界面（编译 worker 没有网格数据）里 `.top[u,w]` 退回包围盒，物体会浮在地形的包围盒顶面上；阵列整体立在地形上（阵列成员各自的高度不同，要写成 `repeat … on=地形.top[…]` 逐实例取高度，语言还不支持）。

### D5 带内凹的旋转体（2026-10-11）

- **做法**（`reverse.mjs` 的 `fitRevolveShell`）：外轮廓（每个高度的最大半径）的误差超过 0.02 时，看网格是不是车削出来的：顶点投到截面 (r, y)（按 10^−3 × 尺寸取整去重）成为“环”，网格的边投过去只连相邻的环。环数 ≤ 200、每环平均至少 4 个顶点、投影图是一条两端的链、一端在轴上，就沿链取截面轮廓，Douglas–Peucker 简化（容差同外轮廓），轴上的端点写成 r = 0（编译器沿轴补齐）。误差按采样点在截面上到轮廓的距离算；不超过 16 个点、比外轮廓好才用。
- 先试过用主曲线（sweepfit.mjs）在截面点上排序：按面积的采样在轴附近很稀，盆底上下两面只差 0.35，中线会在两面之间来回摆；车削网格的拓扑可靠得多。
- **效果**：curves 示例的喷泉水池从网格引用变成与原文逐点相同的 `revolve`；curves L0（结构档）1342 → 1249（−7%）。宿舍区、H1、spaceport、rotation 不变。
- **没做**：倾斜的车削体（rotation 示例里 aim 过的碟形天线：拟合坐标系的轴差一点，环在截面上散开，仍用外轮廓）；不是车削出来的凹形网格。
- **逆向写侧面锚点**（随 D7 一起提交）：直立的物体朝向轴的那个侧面（法线与径向夹角不到 18°）的中心落在竖直圆柱、圆台的侧面上（径向差不超过半个 τ——插进去的不算贴着，spaceport 的摆臂插进火箭 0.3 m，曾在 stud 单位下被写成贴面、镜像校验不过），写 `against=罐.side[θ,v]`（角度、高度比例的位数按弧长、高度误差不超过 τ 取）。候选不靠接触事实（多边形近似的圆柱与贴上去的面差一点，常常没有事实），在中心够近的竖直圆柱、圆台里找。测试：罐体上的接管与牌子逐字写回原文的 `side[37,0.6]`、`side[-160,0.3]`；插进罐里的杆不写。宿舍区、H1 没有这样的东西，分数不变。

### D6 跨进程的评分缓存（2026-10-11）

- **想清楚的一点**：失效条件并不复杂。进程内的增量评分（A4）本来就逐个核对重建物体（键 = 路径 + 颜色 + 世界三角形的哈希），源一侧逐点记着距离与最近的物体；只要源模型、评分代码与常数不变，上一个进程留下的状态就和这个进程里上一次评分留下的一样可用。编译器、工程层文件的任何改动都体现在重建物体的键里，由增量算法自己找出来。
- **做法**：评分后把状态写进源模型一侧的磁盘缓存（`state/cache/score.bin`，种类 score）：逐点的距离与最近物体拼成两个大数组，上一次的物体表、每个物体的残差、路径编号存 JSON；键 = 源模型的键 + 评分相关模块（parts / sidecar / srccache / surfaces / nearest / worldtris / score.mjs 与 package-lock）的内容哈希 + 常数。新进程里这组常数还没有状态时先读回来（源部件的汇总按逐点数据重算）；读不到、对不上就照常全量。重建物体的树改成用到时才建（什么都没变时用不着）。
- **效果**：宿舍区 `score` 命令 5.3 s → 2.3 s（评分本身 3.9 s → 0.9 s，其余是进程启动、读源部件缓存与编译）；改了一处的提议预览只重算受影响的部分。缓存文件约 20 MB（宿舍区）。
- **核对**：宿舍区、H1 的 `score --objects` 输出——无缓存的全量、从磁盘状态的增量、改动前的代码——三份逐字节相同。测试：新的缓存对象（模拟新进程）读回磁盘状态后连续三步改动，与全量逐位一致；键不同时另算一份。

### D7 1e5 部件与分块逆向（2026-10-11）

- **现状**：单进程逆向 10×10 的压力场景（11100 个部件）现在要约 2.5 分钟（拟合 25 s，逆向 121 s：板件 / 外壳 28 s、阵列 37 s、镜像 33 s——比 C4 记录的 64 s 慢，D1 之后的板件、外壳候选与“有内容的物体也参与阵列”都有份）。按此推算 1e5 单进程要 20 分钟以上，内存也吃紧。
- **做法**（`tools/tiles.mjs`、`tools/tileworker.mjs`）：按部件包围盒中心在水平面上做平衡的 k-d 划分（跨度大的轴对半分），每块不超过 maxParts（工程默认 3000）；各块在 worker 线程里独立跑完整的逆向（拟合、类型、阵列、镜像、关系、校验、命名——校验就是局部的），再合并成一份文本，工程照常按位置拆成 base/ 下的文件。各块一致性由 `reverse()` 的三个新选项保证：`nameStats`（名字清理按全场的名字统计）、`typeSeed: 'mesh'`（类型的采样种子按网格编号，同一个网格在各块写出的类型体逐字相同）、`defaultMaterial` 给材质的键（全场最多的那种）；类型名取全场第一个实例（`typeName`）。合并：材质、类型按声明原文去重，同名不同文的在后来那块里改名；物体重名的在那块里改名（块之间没有引用；改名只改引号外、不跟“=”、不在 pin= / axis= 这类符号取值后面的完整标识符）。
- **触发**：工程逆向在部件超过 `project.json` 的 `tiles.threshold`（默认 2 万）且没有决定层时分块（决定层要整体满足）；命令行 `bin/reverse.mjs --tiles[=每块部件数]`，部件超过 2 万自动分块。宿舍区、H1（约 2000 个部件）不受影响。
- **效果**（压力场景，结构档，分块 2000）：3×3（L1，1000 个部件）分块与整体的分数差 2.4%（块边上的关系与阵列），零编译错误；10×10 48 s（单进程约 146 s）；20×20（44400 个部件）189 s，编译结果 17 s；32×32（113664 个部件，64 块）553 s，编译结果（162569 个节点，零错误）74–91 s，进程内存约 12 GB（导出 41 s）。PLAN 的验收线 1e5 < 15 分钟。编译器里两处把几十万个元素展开成参数（`flat.push(...keep)`、导入文件的语句）会栈溢出，改成了循环。
- **没做**：跨块的阵列与镜像（PLAN 的“第二遍合并块边界”：只看每块边缘的实体，把两块里的同一个阵列接起来）；块边上的物体只能参照本块里的东西（多写一些坐标）；分块时不支持决定层；真实的大地图还没有（压力场景是同一个 spaceport 复制的，类型多、跨块重复的东西多）；单进程逆向在 1e4 上变慢的原因（阵列、镜像检测）没有再追。

### D8 角色、分散的模型、按角色显示与评分（2026-10-11）

用户的方向：逆向追求的是语义与功能，不是点和面重合——更像“让 AI 重建场景”。为了省资源，真实地图里的模型本来就分结构性的和装饰性的，名字里看得出来；还有很多零碎的东西装在同一个模型里，包围盒很大、实际体积很小。

- **角色**（`tools/roles.mjs`）：structure / decor / terrain / decal / helper。判定顺序：工程的 `roles.json`（规则数组：`{ role, name?, material?, meta? }`，都是正则）→ 名字里的词 → 几何。名字按下划线、数字、驼峰切词；有贴花、辅助的词就是它，否则取**最后一个**有归属的词（中心词在后：`WallLamp` 是灯，`Road_FlowerBed` 是花坛；最初用子串匹配，`WallLamp` 被当成墙）。白模体积：默认名（Cube、Box…）、≤ 200 个三角形、整个包住 ≥ 10 个别的部件。不能按材质判：H1、宿舍区全场都是 whitebox 材质，第一版这样判，所有东西都成了辅助。宿舍区：结构 391、装饰 1520、贴花 71、地形 15、辅助 3（Cube）；H1：辅助 13（10 个 Cube、3 个 Fog_Cube）。
- **逆向按角色取舍**：辅助不写进几何（文件头注释列出）、评分不计（R_src 与基线 S_mesh 都跳过）；装饰、贴花不试板件、外壳、并、扫掠；贴花一律网格引用、不当参照物。角色写成 `~role=`（结构是默认，不写）。
- **分散的模型**：≥ 3 个连通分量、各分量包围盒体积之和 < 整体包围盒的 10%。结构、装饰的分散模型在拟合差（不是台阶、管、扫掠）时拆成 `group { box … }`，与现在的写法比局部分数，不超过 1.25 倍才拆（语义上偏向拆开；但几十片零件写成几十个盒子远比一行网格引用长——不比分数时 H1 涨了 11%）；不拆的标 `~scatter=块数`，不当参照物（它的包围盒很空）。
- **显示**：界面工具栏按角色的开关（只列场景里有的角色），源模型叠加层按 `state/source-roles.json`（逆向写，键同 `~src`）一起隐藏；`render --only=structure[,…]`（源模型按部件角色，重建按 `~role`，沿路径继承）。
- **评分**：`score` 的 `byRole` 分角色报 S、各项与解释率（重建一侧按物体的 `~role`，源一侧按源部件的角色；各角色的 S 加 unattributed 等于总分）。
- **分数**（结构档，`panels_run`）：spaceport 1217.41（不变）；宿舍区 47950 → 52311（+9.1%），H1 61727 → 63413（+2.7%）——装饰不再拆板件、贴花不再硬套基本体，描述变长，这是有意的语义取舍。逆向时间没有仔细比（init 含读源模型：宿舍区 15 s、H1 19 s）。

  总的解释率（宿舍区 28%、H1 24%）主要来自装饰的享元类型与阵列；**结构几乎没有被解释**，H1 的结构比全写成网格引用还贵。只看结构的对照图上：H1 的几座楼的外墙（`HLight_01_ExterWall_01`、`…_Damage_01/02`、`…_ExterWall_02`、`InterWall_04`）写成了实心的盒子，把楼里的东西整个盖住，每个残差约 700（网格引用约 126）。原因：外墙到外包盒的相对误差 0.10，在结构档的容差 0.25 以内，就直接接受了盒子，没有和网格引用比代价；板件、外壳都试了，都没有结果。宿舍区中间那栋矮楼也成了实心体块（是享元类型的实例，原因没追）。

### D9 结构少用网格：网格按角色计价、体积误差、大部件当小场景（2026-10-11）

用户的要求：重建时应该很少使用网格——项目的本意是让 AI 用一门语言重建场景。用户定的：结构性的物体按真实信息量计价，装饰性的可以用网格（具体由用户决定）；实心体块填满源模型里空着的空间要扣分。

- **为什么以前大部件都留成网格**：网格引用只要 c_mesh × log2(三角形数)，1600 个三角形的外墙约 107；拆成板件要几十上百行。只要这个价钱不变，拆得再好也赢不了。实心盒子能赢网格，是因为评分只量表面距离：盒子的表面正好贴着外墙，楼里的空间填实了也不扣分。
- **网格按角色计价**（score.mjs 的 meshPrice）：结构按真实信息量（4.5 × 顶点数 + 3 × 三角形数：逐点写出来的长度）；地形、装饰、贴花按引用价。工程的 `score.meshPrice` 按角色改。地形本来也按真实信息量，但起伏的地面拆成几十块斜放的盒子既不准、语义也不对（语言里没有高度场），改回引用价。评分在部件没挂角色时按默认规则判（与逆向一致）。
- **逆向配合**：网格变贵之后，以前被网格掩盖的门槛挡住了正确答案：精细档“拟合不好就引用网格”只对引用价的角色保留；按真实信息量计价的部件只要按本档容差拟合失败就试扫掠（spaceport 的弯道：楔形 → 圆弧扫掠）、旋转体的轮廓放宽到 64 个点（精细档的花瓶：楔形 → revolve）。worker 线程的预先拟合拿到角色与价钱；扫掠的采样种子不再随单位变。
- **体积误差 R_vol**（volume.mjs）：重建物体内部撒点（薄的、网格引用不撒），离源表面不到 δ 的不计，在源模型实体里的不计——从这一点沿 6 个轴向打射线，数每条射线穿出（背面）与穿入（正面）的次数，至少 5 条穿出得多才算在实体里（几块实心的墙在墙角互相穿插也对；只有一层的单面立面从里面看会被当成实体，宁可漏判）。其余按 log2(1 + (d − δ)/δ) 计价，权重 c_res × log2(1 + 体积/δ³)，以顶层语句为单位、内部按体积分摊。nearest.mjs 加了沿射线的穿越计数。局部评分（逆向的比价、refine）同样计入。
- **局部评分的两处偏差**（体积项把它们放大了，calibration-refine 测试抓到）：refine 的邻域只取物体自己的源部件周围（一段楼梯的 ~src 只是一级踏步，远端被当成“源模型里没有”）——改成物体现在的几何与源部件的包围盒合起来取；阵列里的一个成员在局部评分里拿一整份权重，全场却是整条语句共享——局部评分接收同一条顶层语句里其余物体的面积与体积（groupContext），按全场的方式分摊。
- **大部件当小场景**（reverse.mjs 的 trySubScene）：结构里拟合不好、2 m 以上、现在的写法分数不低于 120 的部件（已认出的台阶、管、扫掠、旋转体除外），拆成块——互不相连的分量（2–400 块）；只有一块时用板件分解（格子从细到粗）的每条语句——再递归调用逆向（拟合、阵列、镜像、关系；子场景里不再拆子场景，模块状态存下、做完恢复），写成一个组。按面积只留大块（75% / 90% / 97% / 全部）的几种写法一起比分数（细碎的小板写出来不划算就舍掉）。子场景里各块的局部评分按面积分到整个部件的那一份权重；板件已经写好的“大矩形挖洞”原样保留（重新拟合会丢掉洞）；顶层放在原点的组摊平；名字带上板件的 wall、slab。
- **板件的斜边**（panels.mjs 的 slopeRuns）：连续 ≥ 3 列（或行）、一头对齐、另一头单调变化且大致在一条直线上——坡顶的墙、楼梯旁的墙、切角的楼板——以前是一串台阶状的窄条，现在写成矩形 + 楔形。
- **效果**（结构档，panels_run；分数的定义变了，与 D8 之前不可比）：

  | | 宿舍区 | H1 | spaceport L2 |
  |---|---|---|---|
  | 结构的网格引用 | 46 → 2 个（共 100 个三角形） | 105 → 11 个（共 300 个三角形） | 0 |
  | 结构的解释率（新计价下：只改计价 → 现在） | 73% → 84% | 66% → 92% | 99% |
  | 总分（只改计价 → 加体积项 → 现在） | 86794 → 107944 → 79269 | 310534 → 331788 → 110438 | 1110 → 1110 → 1087 |
  | 子场景拆开的部件 | 11 | 45 | — |
  | init 时间（读源 + 逆向） | 15 s → 35 s | 20 s → 104 s | 2–3 s |

  H1 只看结构的对照图上，后面那栋楼的外墙壳拆成了墙、屋顶、门；桁架塔写成了管、杆与镜像对。
- **没做 / 剩下的**：H1 两面“破损”外墙（墙上是不规则的破洞）仍是实心盒子（拆开写约 1500、盒子约 1300）；宿舍区中间那栋矮楼是享元类型（Dormitory_02_InterWall_01，三个实例），类型的路径还没接子场景，类型体里留着一个实心大块；装饰的基本体代理（灌木、车写成盒子）体积误差很大（宿舍区装饰的 R_vol 约 1.4 万），逆向选“代理还是网格引用”时还不看体积项；子场景让逆向慢了 2–5 倍（H1 主要花在几十个大部件各自的递归逆向上），没有优化；拱门现在是一串台阶状的洞（外壳那条路会写成横放的圆柱，子场景里没走到）；分块逆向（tiles）的 worker 里子场景照常运行，没在 1e5 规模上测过。

#### D9 续（2026-10-11）：类型接子场景、长形状要付得起、提速

- **用户发现的问题**：H1 里一根细杆写成了 21 个轮廓点的旋转体。原因：候选形状只按误差比，旋转体把建模与取整的噪声也描了下来；D9 把结构的轮廓上限放宽到 64 点后它就进来了。改成旋转体、扫掠要用省下的残差付得起多写的数（paysOff：误差在 τ 以内不计；形状多出来的面按覆盖率估，距离不超过形状第二小的半尺寸——细杆的方柱多出来的只是棱角，盖住弯道的楔形多出来的离路面很远）。细杆现在是 box，spaceport 的弯道仍是圆弧扫掠。
- **类型接子场景**：享元类型也试小场景（残差按实例数计）；普通部件与类型都先试小场景、再退回“分散的块”（后者每个分量只拟合成一个基本体，宿舍区那栋矮楼的类型体里留下了一个实心大块：三个实例 1241 → 430）。
- **提速**：同一种拆法的变体从粗到细，描述长度已经超过最好的分数、或总分比上一个更差就停；板件的格子先试最粗的；变体共用原点、按整个部件的面积分权重（spaceport 1087 → 991）。worker 线程可以预先算每个部件的组合写法（板件、外壳、并、小场景）：所有不会成为类型实例的部件，按网格分组、动态分配，结果与单线程逐字一致（测试）；worker 里的最近点查询不再开嵌套的线程池。H1 init 163 s → 74 s，宿舍区 46 s → 37 s。
- **试过、没用的**：子场景里按块缓存板件结果（各变体共用）——结果一样，却慢了一半，原因没查清，撤掉了。worker 的并行扩展性差：串行 58 s 的组合写法，2 个线程 68 s、4 个与 8 个都约 48 s（12 个逻辑核），像是内存分配与垃圾回收在争；要继续提速得先做剖析。
- **分数**（结构档，panels_run r13）：spaceport 991，宿舍区 75685（结构解释率 86%），H1 101727（93%）。
