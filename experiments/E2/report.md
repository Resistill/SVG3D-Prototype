## 方法说明

- **读过一次源模型。** 用脚本 `scratch/diag.mjs`（借 `tools/reverse.mjs` 的 `readParts`）读了源 GLB，查罐内部的表面分布。这超出了“只用工具和渲染图”，原因是工具看不到源部件的内部结构。之后没有再这样做。
- **解析过渲染图像素**（`scratch/png.mjs`、`nose.mjs`、`road.mjs`、`roaddiff.mjs`）：量整流罩剪影宽度、路的上下边缘，逐列对比源与重建的路面。量出的整流罩轮廓与 README 例子的数值一致，最后用的是那组取整值。
- **挪过一张图。** `render --out` 相对工程目录解析，`initial-iso.png` 被写进了 `work/e2/experiments/E2/`。我把它挪到 `experiments/E2/`，删了空目录。层文件没碰过。
- **运行期间仓库在变**：HEAD 从 fb4f24e 变成 fe0381d，`tools/agent.mjs` 多了 `fit` / `detect`（不是我改的）。分数链连贯。
- 读过 `src/`、`tools/` 的代码，用来确认 revolve、helix、sweep、材质继承和参数解析是怎么实现的。

## 发现的问题（每类按改进优先级排）

### 分数

1. **refine 返回的 delta 按目标档位的 δ 计算**，和工程分数不一致：001 报 −403.02，实际 +53.01。期望：同时给出按工程 δ 的 delta，符号不同时警告；`--apply` / `--auto` 也应按工程 δ 判断是否写入。
2. **源网格里不可见的内表面按全额计分。** L2 合并网格不做布尔并，罐身里的半球和顶盖、火箭级间端面、门洞底部共面布尔留下的“门槛”面（maxErr = 2 m 的来源）都算进 R_src。外观正确的 revolve 每个罐也要付约 140。期望：明确这是不是有意的设计；如果是，工具里要能看到（例如“封闭外壳内部的表面占比”）；如果不是，按可见性降权。
3. **逐物体的描述长度归属不清，各项加起来不等于 L_stmt。** `over x : group {` 这一行归到第一个子物体；`subtract` 的子语句、`spline` / `helix` 曲线语句不归到任何物体；009 之后 `road` 的逐物体代价从 29 涨到 47，总分却降了 17.8。期望：曲线归到引用它的物体，嵌套语句归到容器，单列“未归属”一项。
4. **`check` 不报分数变化**，想知道值不值只能用掉一条提议。期望：`check --score`，不进预算。

### 工具

1. **没法定位物体内部的误差。** `--mode=error` 按物体平均误差整体上色，厂房残差 18 定位不了。期望：按采样点的双向热力图，或 `inspect --errors` 列出误差最大的采样点坐标。
2. **多行文本参数被静默丢弃。** `bin/s3d-tool.mjs` 的正则 `/^--([^=]+)(?:=(.*))?$/` 不匹配换行，含真换行的 `--text` 落进位置参数；`check` 退回整工程检查，返回“无错误”。`check` 也不认 `--file`，同样静默退回。期望：加 `s` 标志或报错，`check` 支持 `--file`，未识别的参数一律报错。
3. **`inspect --source` 只给包围盒、主轴和建议语句**，看不到轮廓、中线、截面、内部结构。期望：回转体给 `r(y)` 轮廓，扁平体给中线 / 外轮廓，支持 `--section=y`，报告内部表面占比。
4. **`render --cut` 整片丢三角形，不做裁剪**：L2 里大三角形的墙在剖切图中整面消失，剖面也不封口、显示成条纹。期望：按平面裁剪并封口。
5. **`front/back/left/right` 加 `--ortho` 仍然抬高 14°**（`views.js` 里是 `[0,0.25,1]`），不是真立面，量高度要自己换算。期望：`--elev=0`。
6. **`render --out` 相对工程目录解析**，帮助里没写。
7. **`retract` 不删提议的注释**：`edits.s3d` 里留下了“提议 006 …写成样条”（已被撤掉）和“提议 012 …斜撑”（已搬进 014）。
8. **iso 视角配小 `--box` 时取景异常**：相机太近，近平面把画面切掉。
9. **`preview` 的逐物体变化只列 ≥ 0.5 的项**，而且不分 stmt 和残差，做探针时算不出每块的残差。

### 语言

1. **默认 pin 的规则没写清**：repeat / group 按包围盒底面中心定位、没有定位语句的子 repeat 放在父原点，都是靠试才确认的。
2. **布尔切割体与面共面会留下零厚度的皮**（源模型的门槛面很可能就是这样来的）。期望：稳健去掉共面残片，或在文档里提醒切割体要越过被切面。
3. **`turn` 的正方向和 `helix` 的起始角、旋向没有并排写清**；材质沿父级继承在代码里有，文档里没写。
4. **语义库只看尺寸，认错不少**：road 被认成 〔slab platform〕，fuel_line_1 被认成 〔slab〕，tank_1 被认成 〔member beam volume tank〕，arm 被认成 〔slab platform〕。sweep / pipe 应该先按种类判断。
5. **好用的地方**：sweep 可以直接写点列加 `smooth`；保名换形 `over x : group` 不破坏引用；`360/23` 让意图可读。

### 逆向管线

1. **拼成的部件被整体拟合成外轮廓 revolve**：三个罐（各约 140）、火箭（约 100）。源网格里有内部表面，就是“多个基本体的并”的信号，应尝试分解。三个完全相同的罐也没认成阵列，因为比较的是拟合参数而不是源几何。
2. **空心建筑被拟合成实心盒**（fit=0，代价 461，起点最贵）。structure 档应尝试“外壳 − 空腔 − 开口”；refine 的板件候选能拆墙，但拱门写成了台阶状的 hole。期望：开口拟合成矩形 + 半圆拱。
3. **螺旋扶手被拟合成实心圆柱**（236），而同一座楼梯的踏步已经认成了螺旋阵列。期望：拟合 helix 管，并把立柱、踏步、扶手认成一组。
4. **扁平弯曲的路面被拟合成楔形**（fit=0，197）。期望：对很薄的带状部件取中轴线，写成 `sweep section=宽,厚`。
5. **命名大多不对**：`slab_1` / `beam`（输送管）、`column_2`（火箭）、`volume_3..5`（罐）、`tank_2`（扶手）、`slab_3`（摆臂）、`columns_1`（灯杆）、`walls`（尾翼）。
6. **数字没按容差精简**：管道 9–10 个两位小数的控制点（行代价 54 / 48.5）；带噪声的 `rot` 轴应吸附成 `turn`；斜撑应写成 `span from= to=`。
7. **同一物体的几组规律没合成整体**：塔的腿和平台是两组阵列各带一个镜像（见 014）；螺旋楼梯的三部分分散写（见 010）。
