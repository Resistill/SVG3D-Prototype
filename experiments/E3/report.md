## 渲染对比（`initial-iso.png` / `final-iso.png` / `source-iso.png`，取景相同）

**像了的地方**
- **宿舍楼**：五栋塔楼起点都是实心大盒子（Building_Dormitory_01 / 01B / 01C 三个重叠网格各拟合成一个盒子，01C 平均误差 0.72 m）。细化之后，楼板挑出的阳台、立柱、女儿墙、退台都出来了，iso 图里和源模型一眼就能对上。
- **停车棚、装饰构件**（Ornament_01 / 03）：从盒子变成了顶板加立柱、格栅。
- **室内**：水平剖切（`--cut=-110 --view=top`，见 `scratch/cut-rec.png` 与 `scratch/cut-src.png`）对比，房间隔墙、长桌、椅子、沙发、柜子的布局和源模型基本一致。纸箱、盒盖、地垫换成盒子之后看不出区别。椅子、沙发是体素拼的，块状感明显，但仍认得出“座面 + 靠背 + 腿”。
- 植物、岩石、雷达、护栏仍是网格引用，外观和源模型一模一样（这是 003 撤回的结果）。

**还不像的地方**
- **中央下沉广场**（源：带环形台阶、中央水池的下沉院落）在重建里是一整块平板；右侧带金字塔饰件的台阶、坡道也是平板。逆向时就丢了，这次没有预算处理。
- **Building_DormitoryPassage_01**（连廊）仍是一个楔形，平均误差 1.22 m，是现在最差的物体。refine 在它上面崩溃，处理不了。
- **Dormitory_02 的外墙壳**（ExterWall_01 / 01F）细化后主体仍是实心大盒子 `box1 73×48×71`，窗洞、开口都没有。
- 右上方几处窗框（源里是空心的框）换成外包络盒子以后成了实心块。
- 帘子（Curtain_09b，26 个）成了实心薄板，分数上划算（每个从约 144 降到约 79），外观上帘子的褶皱没了。
- 常春藤还有 12 个是盒子（逐个看分数没变差），但它们的源部件被归到相邻的栅栏上，栅栏的分数因此偏高。

## 发现的问题

### 一、分数（按改进优先级）

1. **基础层的记数开销占了大头，AI 却改不了。** 逆向输出的每一行都带 `mat=whitebox`（基础层约 1760 行，计 3520 分），数字一律两位小数（按 0.1 stud = 2.8 cm < δ 取整能省约 5010 分）。两项合计约 8500 分，是终点 S 的 12%，纯属书写开销。AI 只能在自己写的语句里避开：我对 refine 的输出这样做了，提议 017 省了 743 分。建议逆向按档位取数字位数，场景只有一种材质时用默认材质。
2. **逐物体分数的归属会“背锅”，误导判断。** 源部件的残差记到最近的重建物体（`explainedBy`）头上。把常春藤、花藤换成盒子以后，它们的源部件被归到旁边的栅栏、外墙上：002 的预览里分数变差的前几名是 RoadFacility_Ground_D_04B（+822）、ExterWall_01B（+682），这两个物体其实一点没改。真正的“肇事者”只能靠和起点逐物体对比去猜（提议 003 证明了撤回肇事者之后，这些物体也恢复了）。建议 preview 同时给出“因为哪些物体变化”的归因，或者按源部件列出变化。
3. **网格引用逐实例计价。** 同一个网格被 104 个纸箱、26 个帘子、mirror 副本反复引用时，每个实例都付全额 `10·log2(1+tris)`。类型（def）和镜像对网格没有任何压缩收益，和“压缩来自规律”的原则相矛盾。也正因为这样，把网格整批换成盒子才这么划算。
4. **分数没有语义项。** refine 的候选“去掉（由周围的物体解释）”对门框也成立（014，−25）；场景只有 whitebox 一种材质，同材质规则形同虚设，贴花和地面完全等价。“楼和灌木不会消失”只对大件成立，小构件可以凭分数被删掉。
5. **`over 物体 : 新种类`（保名换形）比 `drop` 再重新声明贵。** 换形之后基础层那一行仍然计长度（新节点沿用原来的行号），drop 之后重新声明则不计。于是没被引用的物体我都用 drop + 重新声明（约 11 分；换形要约 22 + 9 分）。这和文档“替换一个物体不会付两份钱”的说法不一致，也会诱导 AI 在能 drop 的地方破坏引用关系。

### 二、工具（按改进优先级）

1. **refine 在 Building_DormitoryPassage_01（wedge）上崩溃**：`Cannot read properties of undefined (reading 'id')`。`refine --auto` 没有逐个物体捕获异常，整轮直接中止：已经接受的 5 项写进了文件，但返回的 JSON（log、start / end）全丢了，这 5 项各自的分数变化不可知。单独 `refine Building_DormitoryPassage_01` 也是同一个错误。
2. **preview / propose 的 `changed` 只给前 20 个**，也没有参数要全表。批量提议（几百个物体）时，只能先 accept，再跑 `score --objects`，自己和旧表对比，才能找出变差的物体。
3. **`render --out` 的路径按工程目录拼接**：给 `experiments/E3/x.png` 会写进 `work/e3/experiments/E3/`（我第一次就这样误写进了工程目录，随后把它移了出来）；给 Windows 绝对路径会拼成 `work\e3\D:\...`，报 ENOENT。只能写 `../../experiments/...`。
4. **refine 每个路径各生成一条提议**，不能把几处细化合成一条提议。预算按条数算时，细化要占很多预算；也没法先看候选文本、不生成提议。
5. **`render --focus` 返回的 `box` 原样传给 `--source --box=`，取景和原图对不上**（聚焦时相机另取景）。文档说这两张图“取景完全一致”，带 focus 时并不成立。
6. `check` 不支持 `--file`：会静默忽略参数，去检查整个工程（返回 `objects: 2000`），而 propose 支持 `--file`。
7. `inspect` 的输出被空间事实淹没（一栋楼有上百条 facts），没有精简模式。
8. `S3D_TIMING=0` 也会打开计时（只判断非空）。
9. 工程的 `project.json` 里，sidecar 指向仓库外的 `../../../SpaceCenter_Rebuild/blockout/layout.csv`，工程搬到别处就不可复现。

### 三、语言（按改进优先级）

1. **没有“默认材质”。** 只能逐行写 `mat=`，或者写一条 `over all() mat=…`（我用了后者）。建议加 `material default …`，或者让场景级的材质声明作为默认值。
2. **集合选择器的 over 不能在属性里引用成员自身**（属性在 over 的环境里求值，没有 `it`）。无法一句写出 `over kind(mesh) where shape=="col_box" : box size=it.w,it.h,it.d`，只能逐个物体生成 1000 多行。
3. **保名换形不保留原来的尺寸**：mesh 换成 box 时 `size` 被丢掉，必须重写一遍。
4. **路径不支持通配**（`Government_Office_Box_01*` 报“表达式不完整”），`where` 里也没有字符串前缀匹配，按名字族选物体只能靠旁路元数据（`shape == "col_box"` 好用）。
5. **退化几何**：refine 产出 `size=77.5,0,64.8` 这种零厚度的盒子当面片用。语言应该有面片（板）原语，或者拒绝零厚度。
6. 基础层的 mirror 写成 `across=(-881.580064,0,0)`，6 位小数，每个数要 3.5 分。

### 四、逆向管线（按改进优先级）

1. **网格保留的判据不看代价。** 逆向在 structure 档“误差超过容差就保留网格”，结果 265 个 `~shape="col_box"` 的纸箱、盒盖，连同帘子、地垫，都保留成了网格（每个约 49–122 分）。换成外包络盒子之后，440 个物体合计省了约 2.4 万分（002 + 003）。判据应该比较“网格代价”和“拟合代价”（文档自己说网格约等于平均误差 2.3 cm 的拟合）。
2. **楼栋整体拟合成实心盒子。** 宿舍楼由 01 / 01B / 01C 三个重叠网格组成，01C 是“楼板 + 柱子”的框架，却拟合成一个 62×91×50 的实心盒子（平均误差 0.72 m）；Dormitory_02 的外墙壳是空心的，内部还有房间，也是实心盒子。refine 的板件或体素一跑就省了几千分。structure 档的逆向应该直接试板件分解。
3. **同一个网格的多个实例没有归成类型**：纸箱 @1…@26 分散在 Mid / Small MeshGroup 里，各写一行 mesh，没有归成类型。
4. **下沉广场、台阶、连廊丢了形状**（平板、楔形），refine 处理连廊时还会崩溃（见工具问题第 1 条）。
5. **植物、岩石、雷达只能二选一**：保留网格（贵），或者用外包络盒子（残差爆炸，还把代价摊到邻居头上）。缺少语义代理（例如用圆柱或球当树冠、用薄板当攀爬植物），semantic 档那套代理在 structure 档用不上。
6. 基础层每行都写了 `mat=whitebox`，数字固定两位小数（见分数问题第 1 条）。这是逆向的输出习惯，不是语言本身的限制，应该在逆向侧修。
